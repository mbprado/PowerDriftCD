# 2026-10-16 European Model 2 BIOS check

**Question/hypothesis:** does the original-code smoke image that falls through to CD PLAYER with the EU Model 1 v1.00 BIOS launch under a different European BIOS revision? **Expected evidence:** main-CPU breakpoint at the initial-program (IP) RAM address followed by `D0 = 0x50443030`, or a visible program screen. **Result:** BlastEm disc launch `FAIL` in the observed Start-button sequence; Genesis Plus GX BIOS load `PASS`, program launch after Start `NOT RUN`; physical hardware `NOT RUN`.

**Verified by execution:** source revision `0e56d8dc01912cdddd91e476d5fe20de09d1f426`, clean before this report; current original IP+SP ISO SHA-256 `8baed93a269c2b1c55f6d006da768eb86aba353a8b32e12c37383f34787ec52d`; host macOS 26.6.2 (25G83), x86_64. The locally supplied, as-labelled `Mega-CD (E) - Model 2 v2.00 (1993).bin` was 131072 bytes, MD5 `9b562ebf2d095bf1dabadbc1881f519a`, SHA-256 `fe608a2a07676a23ab5fd5eee2f53c9e2526d69a28aa16ccd85c0ec42e6933cb`. It was linked only in isolated emulator configuration under `/private/tmp/`; no BIOS bytes were added to Git. **Documented only:** [Genesis Plus GX's firmware documentation](https://docs.libretro.com/library/genesis_plus_gx/) says EU BIOS choice is not locked to a particular revision; this file's label is not independently authenticated by that document.

**Verified by execution:** BlastEm 1.0.0 (official macOS x86-64 archive SHA-256 `2315f5f32b8400b4c56980b87043516ac9ec22aac5fdb9d3bdb97c2b236da221`) ran from a complete isolated copy at `/private/tmp/pd-blastem-eu-m2/` with its `cdbios.bin` symlinked to the Model 2 file. Command: `/private/tmp/pd-blastem-eu-m2/blastem -r E -d /Users/murilo/repos/PowerDriftCD/build/smoke/smoke.iso`. In its main-CPU debugger, `breakpoint 0xff0000; frames 600; binddown "gamepads.1.start"; frames 5; bindup "gamepads.1.start"; frames 300; print/x pc d0` did not hit the breakpoint. After the input sequence, PC was `0x1c4e`, D0 `0xc7`. `bindup "ui.screenshot"; binddown "ui.screenshot"; frames 1` captured the Model 2 CD PLAYER screen at ignored local path `build/evidence/eu-model2-bios/blastem-cd-player.png` (SHA-256 `43f5805842746b74ca3950a19a07bfab109d153157ae8ae95a9f15d86a171e40`). No random input seed or cycle counter was used. The interactive debugger transcript was not saved; the screenshot is the retained raw evidence. **Documented only:** an [independent BIOS boot analysis](https://board.mddc.dev/threads/sega-cd-general.24/) identifies `0xff0000` as the main-CPU IP RAM location; the breakpoint address remains a hypothesis for this candidate until IP handoff is observed.

**Verified by execution:** RetroArch 1.22.2 with the same Genesis Plus GX core binary as the [previous BIOS-backed test](2026-10-16-bios-backed-emulator-check.md) ran the unchanged CUE with the Model 2 BIOS symlinked as `/private/tmp/pd-retroarch-eu-m2/system/bios_CD_E.bin`. The isolated config set PAL region, `system_directory` to that directory, and `pause_nonactive = "false"`. Command: `/Applications/RetroArch.app/Contents/MacOS/RetroArch -v --log-file=/private/tmp/pd-retroarch-eu-m2/run-active.log -c /private/tmp/pd-retroarch-eu-m2/retroarch.cfg -L /private/tmp/pd-retroarch/cores/genesis_plus_gx_libretro.dylib --max-frames=600 --max-frames-ss --max-frames-ss-path=/private/tmp/pd-retroarch-eu-m2/frame600-active.png /Users/murilo/repos/PowerDriftCD/build/smoke/smoke.cue`. Exit status was zero; the log records 131072 firmware bytes loaded and a screenshot after 600 requested emulator frames. Ignored raw copies are `build/evidence/eu-model2-bios/genesis-plus-gx.log` (SHA-256 `c618b822d98c149f158507cb29c27f0de4cbc3a2e5cc43321f019a09d89e3c66`) and `genesis-plus-gx-frame600.png` (SHA-256 `52fa6c975ee48fbe6f554340cf346641a62d3745526addddfab9674910487b51`). The screenshot shows the Model 2 BIOS's `PRESS THE START BUTTON` screen. A first attempted capture paused because RetroArch's `pause_nonactive` was enabled while another GUI held focus; it was discarded and rerun with that setting disabled. No Start input was applied in Genesis Plus GX.

**Inference from the BlastEm result:** changing from the EU Model 1 v1.00 BIOS to the as-labelled EU Model 2 v2.00 BIOS does not overcome this image's launch blocker. **Hypothesis:** missing accepted startup/security content remains a stronger explanation than a single BIOS revision incompatibility. **Unsupported:** the exact BIOS rejection path, program execution under any BIOS, stock-hardware compatibility, or hardware-speed measurements. The renderer gate remains closed.
