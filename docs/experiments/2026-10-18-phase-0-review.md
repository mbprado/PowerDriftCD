# 2026-10-18 Phase 0 review and limited Phase 1 entry

**Decision:** after reviewing the Phase 0 evidence and the explicitly stated original-only boot limitation, the owner agreed to proceed with Phase 1 synthetic characterization in BlastEm. This is a limited GO for experiments using private, locally held startup bytes. It is not a claim that Phase 0's wider toolchain and compatibility questions are settled. The production road renderer remains deferred until characterization results support an architecture. No physical hardware is to be used until the owner explicitly requests it.

| Area | Review finding |
| --- | --- |
| Build pipeline | **Verified by execution:** GNU m68k tools assemble/link the original IP and SP; the Python builder emits reproducible U.S. ISO/CUE images. See [toolchain evaluation](toolchain-evaluation.md) and [U.S. baseline](2026-10-18-us-development-baseline.md). |
| Sega CD boot | **Verified by execution:** BlastEm boots a private U.S. two-track image and runs the original text IP under the owner-supplied U.S. Model 1 and Model 2 BIOSes. The original-only image fell through to CD PLAYER; an original-only boot remains **unsupported**. See [boot evidence](2026-10-18-eu-us-five-second-text-boot.md). |
| Debug access | **Verified by execution:** main and sub 68000 breakpoints, register/memory inspection, level-2 callback, 2M Word RAM ownership and data return in BlastEm. See [callback](2026-10-18-us-level2-callback.md) and [Word RAM](2026-10-18-us-wordram-2m-roundtrip.md) records. VDP register inspection is **verified by execution** in [the emulator comparison](emulator-comparison.md); ASIC busy/latency and VDP transfer timing remain **unsupported**. |
| Timing | **Verified by execution:** the [sixteen-handoff stopwatch test](2026-10-18-us-wordram-stopwatch.md) records emulated counter ticks. Physical-console cycle or wall-clock performance remains **unsupported**. |
| Emulator and automation scope | **Verified by execution:** BlastEm GUI, debugger, requested frame advances and raw PTY transcripts. Headless graphics, unattended input replay, Linux execution and an independent emulator running this IP are `NOT RUN`. The owner chose BlastEm alone for ongoing development; the original two-emulator criterion was superseded. |

**Development baseline:** use U.S. region images with the U.S. Model 2 BIOS for routine BlastEm tests; run Model 1 at [compatibility checkpoints](2026-10-18-us-bios-test-policy.md). Keep the startup prefix, BIOS files and derived private images ignored. Record build/firmware hashes and raw observations for each experiment. The first Phase 1 experiment extends the Word RAM timing batch with explicit modular wrap accounting and a separate timer-bookkeeping control loop. Its output is emulator evidence, not an architectural performance limit for stock hardware.

**2026-10-19 follow-up — verified by execution:** the [2,048-exchange long batch](2026-10-18-us-wordram-long-batch.md) and [four paired paths](2026-10-19-us-wordram-paired-phases.md) passed under the routine U.S. Model 2 BIOS in BlastEm. Their stopwatch totals are composite emulator code-path measurements. These experiments do not close original-only boot, ASIC/VDP timing, or hardware compatibility, and do not authorize the production renderer.

**Open conditions:** establish a lawful, original-only boot path before distributing or claiming the smoke image is independently bootable; investigate ASIC, VDP transfer and frame pacing instrumentation before choosing a renderer; keep hardware compatibility and performance unclaimed until the owner authorizes real-console tests. The current review does not close these questions.
