# 2026-10-18 shared European boot-prefix comparison

**Question/hypothesis:** is the text disc failing because Model 2 changed its BIOS acceptance bytes, or because the disc omits a startup region shared by both European BIOS versions? **Expected evidence:** compare only the first disc sector from the owner-supplied working reference against the owner-supplied BIOS files, without outputting or committing their bytes; check the current original smoke disc as a negative control. **Result:** shared reference/BIOS byte sequence `PASS` by static execution; exact BIOS decision branch `INCONCLUSIVE`; original text-disc boot still `FAIL` in the earlier [Model 1](2026-10-18-simple-text-boot.md) and [Model 2](2026-10-18-model2-text-boot.md) runs. This comparison is L0 structural evidence, not a new emulator or hardware boot test.

Raw JSON results are ignored at `build/evidence/2026-10-18-boot-prefix/reference-match.json` (SHA-256 `48250ee2494e3fe6cee614d3ca38fd24f4044792beb2f1474cd4f122a5e07ab8`) and `smoke-match.json` (SHA-256 `b7af1ba3dca481a52cfb56641f7a036079ce9dc5800db04ab91e5b41ff5a9607`). The negative result means no match meeting that search threshold, not that the BIOS contains no individual smoke bytes.

**Documented only:** Sega's [disc-format bulletin](https://gist.github.com/akiyan/a90d1e7d41ce89c532f29cafc356ccc2) describes a security program at the beginning of IP and an expanded IP/SP layout for later BIOSes. **Inference from the static comparison and prior BlastEm runs:** the two European firmware files share the same 1,390-byte sequence present at the working disc's IP start, while our disc lacks it; a Model 2-only BIOS change does not explain both failures. **Hypothesis:** this sequence is the region-accepted startup/security block required before the original text IP can run. **Unsupported:** the exact BIOS comparison branch, legal redistributability of that block, successful boot after supplying it, sub-CPU SP execution, and physical-hardware compatibility.

**Verified by execution:** the optional `--startup-prefix` path in `tools/make_smoke_cd.py` was checked only with a 1,390-byte synthetic prefix (`bytes(i % 251 for i in range(1390))`). The command `python3 tools/make_smoke_cd.py build/smoke/ip.img build/smoke/sp.img build/smoke/synthetic-expanded.iso build/smoke/synthetic-expanded.cue --startup-prefix build/smoke/synthetic-prefix.bin` produced a local image with IP extension header `(0x800, 0x800, 0, 0)`, SP header `(0x1000, 0x7000, 0, 0)`, the synthetic bytes followed by the unchanged 440-byte original IP at disc offset `0x200`, and the original SP at `0x1000`. Its SHA-256 was `c9ba39d0f0ade6866c4150164a088e7f8c61ae2f2251a3bb9197fcd46a5d6fb9`. `sh scripts/build-smoke.sh` still yielded the same default smoke ISO SHA-256 above. This is a layout check only; synthetic bytes cannot demonstrate acceptance by the Sega BIOS.
