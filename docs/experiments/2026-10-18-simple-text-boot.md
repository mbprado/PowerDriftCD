# 2026-10-18 original text payload and disc boot check

**Question/hypothesis:** can a small original main-CPU IP display `HELLO SEGA CD` after a stock Mega CD BIOS launches the disc? **Expected acceptance:** BlastEm hits main-CPU PC `0xff0000` for the disc, then shows the text and `D0 = 0x50443030`. **Result:** text rendering `PASS` in a separate Genesis cartridge preview; Sega CD disc boot `FAIL` in the observed European BIOS sequence; physical hardware `NOT RUN`. The preview is not disc-boot evidence.

## Interpretation and next gate

**Documented only:** Sega's [disc-format bulletin](https://gist.github.com/akiyan/a90d1e7d41ce89c532f29cafc356ccc2) says the revised U.S. BIOS expects a supplied security program at the beginning of IP and describes the expanded header layout. The [Blast SDK](https://github.com/retro16/blastsdk) likewise instructs developers to extract CD boot code for its Sega CD ISO builder. These documents do not independently prove the exact rejection branch of the tested EU or Japanese BIOS.

**Hypothesis:** the absent region-accepted security/startup block is the remaining boot obstacle. **Unsupported:** the exact BIOS rejection comparison, execution of this disc's IP or SP, compatibility with stock hardware, or frame/cycle performance. The earlier [Sonic reference control](2026-10-17-reference-boot-control.md) verified that BlastEm can reach a working disc's IP with the same EU BIOS and MODE1/2048 format; it did not license or supply reusable startup code. The owner chose BlastEm alone for future emulator tests, so an independent-emulator text-disc pass was `NOT RUN`. The original-code renderer is ready for a normal IP handoff, but the Phase 0 boot gate remains closed.
