# 2026-10-18 U.S. BIOS test policy

**Owner decision:** use the owner-supplied U.S. Model 2 BIOS as the routine BlastEm configuration. Run U.S. Model 1 at compatibility checkpoints. This is a test-priority decision, not a claim that the two firmware versions or physical Sega CD models are equivalent. The owner's belief that Model 2 is more prevalent is a planning preference here; population share was not measured by this project. No physical hardware is to be used until the owner explicitly requests it.

**Verified by execution:** the [private five-second text disc](2026-10-18-eu-us-five-second-text-boot.md) booted under both U.S. BIOS files. The [main/sub-CPU handshake](2026-10-18-us-subcpu-handshake.md), [level-2 callback](2026-10-18-us-level2-callback.md), [2M Word RAM round trip](2026-10-18-us-wordram-2m-roundtrip.md), and [sixteen repeated 2M handoffs](2026-10-18-us-wordram-repeat.md) passed under both. In the [stopwatch feasibility test](2026-10-18-us-wordram-stopwatch.md), two boots per BIOS passed all sixteen handoffs; the full-batch readings were 51 ticks with Model 1 and 52 with Model 2. One timer tick is the measurement resolution, and these BlastEm observations do not establish a meaningful performance difference or physical-console timing.

**Verified by execution:** the U.S. Model 1-derived, locally held startup prefix booted the same private disc under both BIOS files. A candidate prefix extracted from the Model 2 BIOS fell through to CD PLAYER under that same Model 2 BIOS. The exact cause is **unsupported**. Routine Model 2 testing can use the already passing private disc, but its startup-prefix provenance must be recorded; a successful Model 2 BIOS run does not validate a Model 2-derived prefix or the original-only disc. The private prefix, BIOS files, generated images, and raw emulator logs remain ignored locally.

**Documented only:** Sega's [Sega-CD Technical Bulletins](https://segaretro.org/images/2/2e/Sega-CD_Technical_Bulletins.pdf) describe Mega-CD 2 BIOS calls as compatible through their call interface, while noting changed drive-open behavior: on Model 2, open/close status does not change until the user manually operates the tray. Disc changes and drive-command timeouts therefore warrant explicit Model 1 and Model 2 checks. This documentation does not prove all timing or hardware behavior is identical.

**Routine test:** build a U.S. region image and run it under the pinned BlastEm U.S. Model 2 BIOS. Record the source revision, image checksum, BIOS checksum, startup-prefix checksum if applicable, result marker, and raw log. Keep emulator tick counts separate from hardware or wall-clock performance claims.

**Model 1 checkpoints:** run the same U.S. image under the pinned U.S. Model 1 BIOS after changes to disc layout, startup/security bytes, BIOS calls, CD drive/audio/disc-change behavior, or main/sub-CPU coordination; at each milestone before declaring the feature compatible; and whenever a Model 2 result differs from the prior baseline. For changes confined to a benchmark's internal arithmetic or data collection, the Model 2 run is sufficient for iteration, with a Model 1 checkpoint before relying on the result for a project decision. Compare the two BIOSes using identical disc bytes where possible. If either fails, investigate both and record the exact difference before calling it model-specific. EU checks remain selective regressions under the U.S. development baseline.

**Limits — unsupported:** no independent emulator or physical console has validated this policy's coverage. The owner-supplied filenames identify the two BIOSes as Model 1 and Model 2, but firmware identity was not independently authenticated. Model 2 BIOS execution in BlastEm cannot substitute for a future test on a physical Model 2, and the owner's future console configuration must be recorded when hardware testing is authorized. The original-only image remains unverified as bootable. The Power Drift renderer stays behind the Phase 0 review gate.
