# 2026-10-18 U.S. sub-CPU level-2 callback

**Question/hypothesis:** does a main-CPU INT2 request invoke the third `MAIN` system-program callback on the sub-CPU, separately from the main-loop callback? **Expected evidence:** a breakpoint at the interrupt callback is reached with command `PD` and status zero; only that callback writes `I2` to status slot 7; the main CPU then reaches `I200`. **Result — verified by execution:** `PASS` in BlastEm with the owner-supplied U.S. Model 1 and Model 2 BIOS files. This establishes the callback path in the emulator, not real-hardware interrupt behavior or latency.

**Documented only:** the [Mega-CD BIOS manual](https://segaretro.org/images/archive/4/44/20190509114241%21MCDBios.pdf) identifies `_usercall2` as the level-2 interrupt routine, and the [Sega CD technical bulletin](https://segaretro.org/images/2/2e/Sega-CD_Technical_Bulletins.pdf) says it runs following CD-SYSTEM processing. The [hardware manual](https://segaretro.org/images/5/51/Mega-CD_Hardware_Manual.pdf) describes the main-to-sub interrupt request. The prior [handshake experiment](2026-10-18-us-subcpu-handshake.md) verified a reply from `main_loop`, so this build deliberately leaves that callback as `rts` and replies only from `interrupt`.

**Implementation and baseline:** `scripts/build-level2.sh` assembles the original smoke IP/SP with `LEVEL2_TEST=1`, then uses the same ignored local U.S. startup prefix and generated silent CD-DA track as the earlier private boot. The IP writes command `$5044` (`PD`) to main `$A1201E`, requests INT2 through `$A12000`, and waits for reply `$4932` (`I2`) at `$A1202E`. The SP `interrupt` callback checks the mirrored command at `$FF801E`, writes `$4932` to `$FF802E`, and sets D2 to `$49323030` (`I200`). The IP sets D3 to `I200` after receiving the reply. The source remains a one-shot experiment; it does not implement a reusable interrupt service or timing protocol.
