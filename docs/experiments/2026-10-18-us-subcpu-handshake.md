# 2026-10-18 U.S. main/sub-CPU handshake

**Question/hypothesis:** after the private U.S. text disc boots, does its original sub-CPU `MAIN` system program execute a callback, and can the main CPU send a command and receive a reply through Sega CD communication registers? **Expected evidence:** the sub-CPU initializer leaves `SP00` in D1; a `PD` command appears at both CPUs' command slot 7; the sub-CPU writes `SP` to status slot 7; the main CPU reaches its `MS00` completion marker. **Result — verified by execution:** `PASS` in BlastEm with both owner-supplied U.S. Model 1 and Model 2 BIOS files. This is an emulator-level result, not a physical-hardware boot or timing result.

**Documented only:** the [Sega Mega-CD hardware manual](https://segaretro.org/images/5/51/Mega-CD_Hardware_Manual.pdf) describes the main/sub communication registers and main-to-sub level-2 interrupt request; the [software development manual](https://segaretro.org/images/archive/6/6f/20190509144929%21Mega-CD_Software_Development_Manual.pdf) and [BIOS manual](https://segaretro.org/images/archive/4/44/20190509114241%21MCDBios.pdf) describe the `MAIN` module callbacks. The prototype uses main `$A1201E` / sub `$FF801E` for command word 7 and sub `$FF802E` / main `$A1202E` for status word 7. It writes `$81` to the high byte of main `$A12000` after sending the command, requesting INT2 while retaining interrupt enable. The observed control word after completion was `$8001` on the main side.

**Baseline and failure — verified by execution:** the earlier private text image reached the original sub-CPU initializer: D1 was `$53503030` (`SP00`), and sub RAM `$6000` contained `MAIN`. Both communication words were initially zero. The first handshake build wrote `PD` but did not request INT2; both CPUs saw the command, while status remained zero and the main CPU stayed in its wait loop. A debugger write of `$8101` to main `$A12000` then reached the sub callback at `$603C`, produced status `$5350`, and allowed the main CPU to reach D3 `$4D533030` (`MS00`). This isolated the missing interrupt request. Raw transcripts: ignored `build/evidence/2026-10-18-us-subcpu-handshake/baseline-subcpu.log` and `manual-int2-model1.log`.

**Implementation:** `scripts/build-handshake.sh` assembles the original IP/SP sources with `HANDSHAKE=1`, uses a locally held U.S. startup prefix, and creates an ignored two-track private image with an original silent CD-DA track. The default `scripts/build-smoke.sh` build keeps the text-only IP/SP. The SP `main_loop` callback replies when command slot 7 contains `PD`. The IP writes `PD`, requests INT2, waits for `SP`, then marks completion in D3. The reply is intentionally minimal; it is not a general message protocol.
