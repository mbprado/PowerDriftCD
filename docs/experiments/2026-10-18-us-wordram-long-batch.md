# 2026-10-18 U.S. Model 2 Word RAM long-batch timing

**Question/hypothesis:** can a fixed, longer 2M Word RAM exchange run pass data checks while the 12-bit Sega CD stopwatch wraps, and can a separate timer-bookkeeping loop expose measurement overhead? **Expected evidence:** 2,048 numbered exchanges complete, control and exchange counters each reach `$0800`, the exchange tick accumulator passes 4,095 with an observed wrap, and two boots reproduce the same results. **Result — verified by execution:** `PASS` twice under the owner-supplied U.S. Model 2 BIOS in BlastEm. This is the first synthetic characterization experiment after the [limited Phase 0 review](2026-10-18-phase-0-review.md).

**Documented only:** Sega's [Mega-CD Software Development Manual](https://segaretro.org/images/archive/6/6f/20190509144929%21Mega-CD_Software_Development_Manual.pdf) describes the shared main-side `$A1200C` stopwatch as a 12-bit counter with nominal 30.72 µs ticks. The main CPU can read the counter but does not reset it here. The earlier [sixteen-handoff test](2026-10-18-us-wordram-stopwatch.md) recorded short modulo differences but could not distinguish an unseen complete wrap.

**Method:** `scripts/build-wordram-long.sh` creates a private U.S. two-track disc with an original 398-byte IP, the existing original SP callback assembled in long-command mode, the ignored local U.S. startup prefix, and generated silence. The IP switches to 2M mode through the sub-CPU callback. It first runs 2,048 timer-bookkeeping iterations without Word RAM exchanges, then runs 2,048 numbered command/ownership/INT2/return exchanges. The SP validates both main-written words and returns two transformed words on every exchange; the IP verifies both returned words before counting completion. The SP's long-command condition recognizes `$6xxx` commands, including the issued `$6001..$6800` range; the previous sixteen-command build retains its original decoder and binary checksum. The IP leaves `L2OK` in D3 only after all checks pass. No arcade ROM or game asset is used by this experiment.

**Timer accounting:** each loop takes two stopwatch samples per iteration plus one final sample. A sampler records the modular difference from the previous read, adds it to a 32-bit accumulator, counts each observed decrease as a 12-bit wrap, and tracks the largest modular gap. This includes timer-sampling and bookkeeping instructions in both loops. The control loop also performs its loop count and command-number arithmetic but no Word RAM transfer, interrupt request, reply poll, or data validation. Subtracting the control ticks from the exchange ticks is therefore only a rough composite contrast, **not** an isolated handoff latency. The accounting assumes no single gap between reads spans a complete 4,096-tick lap; that condition cannot be independently proved from a 12-bit counter alone. A stalled exchange has no in-program timeout and needs debugger inspection.

**Interpretation — verified by execution for raw counts:** both boots reproduced 3,307 control ticks and 9,289 exchange ticks. The arithmetic difference is 5,982 ticks across 2,048 iterations, but it combines all work omitted from the control loop and any differing loop effects. It is not a per-handoff measurement and does not rank BIOSes or hardware models. **Documented only for conversion:** nominally, the full exchange batch is about 285.36 ms of emulated stopwatch time if no sample gap hid a complete lap. This is neither host wall-clock time nor measured console performance. A U.S. Model 1 run is `NOT RUN` here under the [routine Model 2 policy](2026-10-18-us-bios-test-policy.md); it is due before using a future result for an architecture decision.

**Limits and next action:** this validates the longer path in one emulator and BIOS, not on physical hardware. The recorded maximum modular gap of 17 ticks does not by itself rule out an aliased 4,096-tick stall in a sample gap; a separately bounded timing source or a shorter external observation window is needed to prove that. The timer-only control does not separate CPU processing, Word RAM arbitration, interrupt latency, and BIOS scheduling. Investigate those components and graphics ASIC/VDP observability before selecting a renderer design. Original-only boot and headless execution remain open; no physical test is authorized.
