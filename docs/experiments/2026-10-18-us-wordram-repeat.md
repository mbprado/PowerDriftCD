# 2026-10-18 U.S. repeated 2M Word RAM handoffs

**Question/hypothesis:** does the one-shot [2M Word RAM round trip](2026-10-18-us-wordram-2m-roundtrip.md) remain correct across sixteen consecutive ownership switches? **Expected evidence:** the main CPU completes commands `$6001` through `$6010`, verifies both words returned from each sub-CPU callback, records sixteen completions, and finishes with a command-specific `$A010` reply. **Result — verified by execution:** `PASS` in BlastEm under both owner-supplied U.S. Model 1 and Model 2 BIOS files. The result is functional emulator evidence, not a timing or stock-hardware claim.

**Documented only:** Sega's [Mega-CD Software Development Manual](https://segaretro.org/images/archive/6/6f/20190509144929%21Mega-CD_Software_Development_Manual.pdf), also held locally under ignored `REF/`, describes MODE, DMNA, and RET in the memory-mode register. The [hardware manual](https://segaretro.org/images/5/51/Mega-CD_Hardware_Manual.pdf) describes 2M Word RAM switching. This experiment keeps the previously verified 1M-to-2M setup, then yields with main-side DMNA and returns with sub-side RET on each command. The local Sega-authored manual is a reference copy, not a tracked project asset.

**Implementation:** `scripts/build-wordram-repeat.sh` assembles the original smoke IP/SP with `WORDRAM_REPEAT_TEST=1` and creates an ignored private two-track U.S. image from the locally held startup prefix and generated silent CD-DA. After the sub-CPU switches to 2M mode and returns ownership, the main CPU sends sixteen numbered commands. For command `$6000+n`, main writes the command and its bitwise complement to `$210000/$210002`, yields Word RAM, then requests INT2. The sub-CPU checks both seed words at `$090000/$090002`, writes the complement and command XOR `$5A5A`, returns Word RAM, and replies with `$A000+n`. The main CPU waits for the matching reply and RET, verifies both transformed words, clears the command to avoid replay, and increments its completed count. A bad seed produces `$E000+n`; a reply or data mismatch produces the `RERR` main marker. The fixed successful completion marker is `R160` in D3 with sixteen completions in D5. Wait loops have no timeout, so a missing interrupt or ownership change requires debugger inspection.
