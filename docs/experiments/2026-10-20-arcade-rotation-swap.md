# Phase 1B: rotation-buffer swap and first displayed response — 2026-10-20

**Question / hypothesis:** does the steering-derived Y-Board parameter block reach the rotation buffer used for drawing, and when does its first visible change occur? **Baseline:** [rotation-consumer experiment](2026-10-20-arcade-rotation-consumer.md). **Acceptance:** observe the actual swap-triggering read; reconstruct the 32-byte block immediately before and after it; repeat centered/left controls; compare nearby screenshots; and preserve the prior replay. **Result — PASS, verified by execution in MAME:** the first steering-dependent pre-swap block appeared after callback 962, and the first different screenshot was callback 963. The read repeated every two callbacks, with twelve parameter-area writes between reads. This identifies a working emulated display path, but the underlying arcade track/camera variable names remain **unsupported**.

**Documented only:** [MAME 0.289's Y-Board map](https://raw.githubusercontent.com/mamedev/mame/mame0289/src/mame/sega/segaybd.cpp) routes a Y sub-CPU read at `$198000–$19FFFF` to `rotate_control_r()` and maps `$180000–$1807FF` as rotation RAM. [MAME's video implementation](https://raw.githubusercontent.com/mamedev/mame/mame0289/src/mame/sega/segaic16.cpp) exchanges rotation RAM and its private buffer on that read. `rotate_draw()` consumes six 32-bit values at buffer word indices `0x3F0–0x3FB`: source origins X/Y and four affine increments. [MAME Lua memory taps](https://docs.mamedev.org/luascript/ref-mem.html) run after a read or before a write; the experiment used that documented ordering without altering upstream MAME. These are claims about this emulator implementation, not independently verified Y-Board electrical timing.

**Verified by execution:** the scripted coin/start/pedal sequence and steering baseline were unchanged. ## Swap sequence and visible change

**Verified by execution:** all five refined runs exited zero, logged 33 rotation-control reads after callbacks 956, 958, …, 1020, and logged exactly twelve 16-bit parameter-area writes between each pair of reads. Across 32 comparable successive swaps per run, the post-swap mapped block equaled the previous pre-swap block **32/32 times**. This matches the exchange in MAME's source. The two centered runs and two left runs matched byte-for-byte within condition for all 48 early RAM captures, seven scheduled rotation captures, 33 pre-swap blocks, 33 post-swap blocks, and eleven nearby screenshots. The right run matched the prior uninstrumented right condition's early RAM, scheduled rotation captures, and callback-1020 screenshot.

**Interpretation — hypothesis:** the main CPU's smoothed steering response contributes to an arcade rotation transform, whose first changed block reaches MAME's draw buffer at the next rotation-control read. This supports recovering a transform sequence for one arcade section. **Unsupported:** calling any specific shared word “camera yaw” or “bank,” separating player-car and world-camera motion, proving that all changed pixels came from the rotation layer, mapping this transform directly to the Sega CD five-word commands, or treating MAME callback spacing as stock arcade timing. The emulator source identifies the buffer operation, but no independent Y-Board or second-emulator validation was done.

**Next bounded experiment — hypothesis:** capture a short sequence of the six affine parameters and observable road landmarks at the same deterministic Stage 1 interval; test whether the parameter changes predict the road's screen displacement. Only then attempt a clearly labeled candidate adapter into the Sega CD camera interface. Preserve the existing synthetic renderer and do not infer full track data from this steering pulse alone.

**Follow-up — verified by execution in MAME:** [the affine road-correspondence analysis](2026-10-20-arcade-affine-road-correspondence.md) found that the captured parameters explain 94–98% of exact RGB pixel positions in a road-containing rectangle for the first two affected frames. Later whole-frame correspondence declines, so source-layer differences remain an open question.
