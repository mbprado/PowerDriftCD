# Phase 1B: first controlled Power Drift Stage 1 replay — 2026-10-20

**Question / hypothesis:** can MAME 0.289 reproducibly enter a real Power Drift race from a fixed coin/start/pedal schedule, giving Phase 1B a stable early-track reference? **Expected evidence:** the same visible Stage 1 section in independent runs, frame-indexed private screenshots, identical input-action logs, and clear limits on what the images reveal. **Result — PASS, verified by execution:** three bounded 1,800-callback runs reached Stage 1. The two runs from fresh isolated MAME working directories produced byte-identical screenshots at all six checkpoints. This is an emulator observation baseline, not recovered track geometry or camera state.

## Input inventory and method

**Verified by execution:** MAME `-listxml pdrift` reports one player, a paddle, and pedal controls. A one-second Lua enumeration of `manager.machine.ioport.ports` identified `:GENERAL` fields `Coin 1` and `1 Player Start`, `:ADC.5` field `Paddle` (range 32–224, default 128), and `:ADC.4` field `P1 Pedal 1` (range 0–255). The private XML and input-enumeration logs have SHA-256 `10faed5333e3265f7edbf39abcc359642817ab740937aba305a19489d66d9936` and `86e27b634ccc1e89e347acfdd353d7ddbb412972e158b2d3a5227436cf3ee85b`. MAME's [Lua input API](https://docs.mamedev.org/luascript/ref-input.html) documents `field:set_value`; its actual effect on this game is demonstrated by the transition from attract mode to Stage 1. The pedal field has not yet been isolated against a no-pedal race control, so its in-game meaning remains a **hypothesis**.

**Verified by execution:** original tracked [`tools/phase1b_mame_input.lua`](../../tools/phase1b_mame_input.lua) (SHA-256 `7480754bf91bc3aebf81a8870e14d0e2f938ff095f0df8cbdcb98dfbd492970b`) sets centered paddle value 128, pulses Coin 1 at callbacks 60–64, pulses 1 Player Start at 130–134, and sets Pedal 1 to 255 from callback 240 onward. The script logs each action and saves screenshots at callbacks 300, 600, 900, 1200, 1500 and 1800. The count is the Lua `register_frame_done` callback count, not a recovered arcade camera/frame counter. No steering changes or random inputs were scripted.

**Visual observation — verified by execution:** private screenshots show a transition/title scene at callback 300, a `STAGE 1` start screen at 600, and a playable road with the player's car at 900, 1200, 1500 and 1800. The displayed road/camera and car positions change across those checkpoints. This identifies a repeatable *visible interval* from Stage 1 start through an early road section; it does not identify track segment numbers, world coordinates, camera position, banking angle or physics variables.

## Next bounded experiment

**Hypothesis:** varying only one control during callbacks 900–1500 while keeping the coin/start schedule fixed can separate player steering or acceleration effects from the repeatable road sequence. First compare screenshots and visible HUD state against the fresh-run baseline; then inspect a small, explicitly named RAM window or debugger write trace around a divergence. Candidate addresses must remain unlabeled until controlled variation and code/data references support an interpretation. The existing Sega CD five-word camera interface has not been exercised with arcade-derived values, and this test provides no evidence that it can represent the observed curve/elevation behavior. REA/Ghidra analysis and asset extraction were **not run**.
