# Wider road geometry in the 128×64 ASIC pipeline — 2026-10-23

**Hypothesis:** the existing five-word camera-command pipeline can render and display an original road region near the [host fixture's seven measured widths](2026-10-22-wide-host-road-fixture.md) at 30 Hz. **Baseline:** the [validated 128×64 live-command pipeline](2026-10-20-wide-live-road-pipeline.md), which displays a synthetic road at most 32 output pixels wide. **Acceptance:** preserve that control image, check the new 60-frame ASIC output against independently generated word sums and sampled Word RAM words, observe VDP display, and measure three U.S. Model 2 cold boots for two-VBlank cadence and upload deadlines. **Result — verified by execution in BlastEm 1.0.0: PASS for this synthetic wide-road case.** All three 60-update runs completed without recorded cadence or upload misses; one final screen was visually inspected. No physical hardware was tested.

## Isolated scene and correctness

**Verified by execution:** `runtime-live-wide-geometry` retains 128×64 output, the existing five camera words, 64 scanline traces, 2M Word RAM handoff, 4,096-byte main-RAM staging and VDP DMA, and the two-VBlank scheduler. It changes only this experimental build mode's source stamp map and X sampling: five adjacent original-art stamp columns contain a 56-source-pixel road, and the four depth bands use X steps `(10,5,5,4)` eighth-pixels. The 56-pixel strip produces **89–90 contiguous road-region output pixels at rows 25–32** across all 60 host packets (480 row checks), with no edge clipped at X=0 or 127. [Host metrics](data/wide-road-geometry-host-metrics.json) include every row's bounds and expected word sum. These widths are close to the seven centered arcade reference rows' 89–96 output pixels; lateral position, shape outside those rows, and camera motion are not matched to the arcade. The original control build was reproduced byte-for-byte: IP SHA-256 `531157df45d6aa6bdaf507a9520f7cef1caa5c9978708b3df9ffdf66b3b11ea6`, SP `fd5d710219b357e2cf9bf368a9d6917c1536d7289cd09b276c8dc96b95340002`, ISO `bf5e039a80ed3dff90cd9557e284b49839b4193b99bd0f16ea9255af5d20669e`.

**Verified by execution:** the new disc's IP/SP/ISO SHA-256 values are `695902119a4b7e55cb19dc30b338ece4c269079c186ddac5b2955838152ea39f`, `9121ed4e0e73efff1ef13a3ca2468d7b258d457e35231dcd996424c623122447`, and `91c1e6ecf4e1f5b0df30b8059fbdefcb9606e139eaa083a81cb76a2bb4fa6e82`. The program checked all 2,048 ASIC output words through an additive expected sum before each of the 60 uploads, reaching `GVOK` (`d3=$47564F4B`, `d6=60`) in all three runs. At the final output of run 1, eight sampled Word RAM words at word indices `0,1,63,64,511,1023,1535,2047` exactly matched the host reference: `$3333,$2223,$2222,$2222,$7777,$7777,$7777,$77AA`. This is stronger than the sum alone, but is not a complete word-for-word output comparison.

**Verified by execution:** the BlastEm window visibly displayed the generated wide road and its shoulders, grass and lane marks. ## Timing and transfer

**Verified by execution:** all values below are 12-bit Sega CD stopwatch ticks as emulated by BlastEm, not host wall-clock speed or measured stock-hardware timing. Each run recorded 60 output records and 59 subsequent VBlank intervals. The three [parsed records](data/wide-road-geometry-model2-run1.json) ([run 2](data/wide-road-geometry-model2-run2.json), [run 3](data/wide-road-geometry-model2-run3.json)) contain identical per-frame values. Min/median/max below exclude the first frame for the ready-since-prior-VBlank counter; other windows include all 60 frames. Ownership includes preparation, ASIC activity and Word RAM return. Staging includes checksum plus the 4 KiB main-RAM copy; VDP upload includes DMA setup. Neither window is a pure CPU-cycle count.

**Inference from verified execution:** the wide-road variant has the same 4 KiB ASIC output and VDP transfer size as the control; its isolated ASIC busy window and upload window did not increase. The worst recorded image-ready time rose by 16 ticks, leaving about **211 ticks** before the approximately 1,086-tick upload edge, versus about 227 ticks in the prior control. Additional stamp initialization and changed trace parameters occur inside composite windows; the present counters do not isolate their individual costs. The earlier control runs were performed on a prior date, and test order was not alternated with the new runs. The byte-identical control rebuild supports comparability but does not make this a contemporaneous A/B timing trial.
