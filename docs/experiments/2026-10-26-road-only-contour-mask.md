# Phase 1B: 16B-masked road-contour window — 2026-10-26

## Question and method

**Hypothesis:** the previously calibrated arcade road rows can be checked against a measured 16B composition mask, preserving only edges that are visible from the rotation/Y-sprite stage. **Baseline:** screen-980 [foreground sprite attribution](2026-10-26-screen980-16b-sprite-producer.md), the existing causal edge cases and the fixed [coordinate calibration](data/phase1b-road-calibration.json). **Acceptance:** three deterministic MAME replays must reproduce screens 960–982 and the earlier point probe; the 16B mask must identify the two known screen-980 occlusions; every row used in the prior host comparison must be explicitly classified before its error is reported. The camera packets, art and calibration remain fixed.

**Verified by execution in isolated MAME 0.289:** an additional [small screen-update probe](../../tools/phase1b_mame_layer_rows.patch) records the 16B bitmap word, priority byte and final palette index for x=0–319, y=153–163 at native frames 966–980. The [offline audit](../../tools/phase1b_road_only_contour.py) applies MAME's exact 16B priority comparison to both detected edge pixels. It labels a row `16b_occluded` if either edge is replaced, `rotation_fill` if an edge has fill priority, and `clear_visual_candidate` otherwise. A clear visual candidate is **not** automatically a causally proven road edge. Existing source-hide evidence is required for the selected calibrated rows.

## Observations and geometry comparison

**Verified by execution:** the three replays produced identical layer CSVs for all 15 native frames and equal decoded RGB screens 960–982 to the preexisting baseline. The new frame-979 row capture agrees with all twelve points in the earlier layer probe. Across the 15 composed screens 967–981, the existing color detector found 88 rows in the captured Y window: **77 clear visual candidates, 11 with a 16B-covered edge, and zero classified as rotation-fill edges**. Occluded rows are screen 972 Y=156; screens 973 and 974 Y=157–160; and screen 980 Y=157–158. Screen 980 Y=159 remains a clear visual candidate. These are screen pixels and frame labels, not world-track coordinates or console timing measurements.

**Verified by execution:** all 40 selected case-row entries in the prior calibrated comparison are 16B-clear and match the newly captured screen edges. They represent **23 unique arcade screen/Y rows**, because two original-art variants reuse screen 967 or 975. Their earlier source-hide evidence established two-sided causal changes. Consequently, 16B occlusion does not explain the prior host-shape discrepancies in those selected rows. The remaining 54 clear visual candidates have no new causal source attribution here and are not promoted into camera targets.

**Verified by execution of host comparison software:** those scores reproduce the existing original-art 128×64 **host preview** cases under the tracked calibration. The calibration maps arcade Y=134–190 to output rows 0–63 by nearest-even rounding, and output pixel centers to arcade X using `(10*x+3)/4`; it is a project design choice, **not** a recovered arcade projection. The check width errors for screens 975 and 967 exceed the existing 2-output-pixel check limit. Screen 967's check mean edge error exceeds it too. **Inference:** the prior held-row mismatch survives removal of 16B-contaminated edges. This does not prove that the five-word interface lacks a degree of freedom: prior bounded sweeps found other packets capable of fitting screen 967 when check rows were used as an oracle. A rule that predicts the packet from earlier arcade state remains **unsupported**.

**Decision:** layer capture and selected-row attribution `PASS`; forward camera prediction `INCONCLUSIVE`. In particular, the frozen screen-980 packet still has only one two-sided Y-sprite causal row after masking, below its three-row gate. No camera-interface, renderer, art or Sega CD performance claim is changed.

**Limitations:** the geometry scores use already generated host previews, not Genesis VDP frames. No new BlastEm disc, second arcade emulator, physical arcade board or physical Sega CD was run. The 77 clear visual candidates include rows without causal source evidence, so this test does not reconstruct a real track segment or establish a predictive camera adapter. MAME host speed is irrelevant to arcade or Sega CD hardware timing. The first dry-run of the patch had a malformed hunk count; it was corrected before application, build or replay.
