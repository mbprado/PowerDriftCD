# Phase 1B: screen-980 right-edge 16B sprite record — 2026-10-26

## Question and method

**Hypothesis:** one active 16B sprite descriptor supplies the two screen-980 right-edge pixels at `(290,157)` and `(291,158)` that [the layer probe](2026-10-25-screen980-road-layer-attribution.md) attributed to the 16B bitmap. **Baseline:** callback-979 source RAM and layer captures from the existing deterministic MAME replay. **Test:** in three saved-state replays, change only the descriptor's documented hide bit after callback 979; compare captured RAM, screens 960–980, and before/after composition indices. **Expected evidence:** exactly one RAM byte changes, earlier screens remain equal, and both target pixels lose their 16B word.

## Result

**Verified by execution in isolated MAME 0.289:** callback-979 B-sprite RAM record 4, byte offset `$0040` in the 4 KiB RAM mapped at `$188000`, supplies both pixels. The record spans native Y=57–182 and has palette field `$2E`; MAME's decoded `colpri=$2E0`, combined with pixel nibble `2`, matches the baseline B-sprite word `$02E2` (738). The one-byte intervention changes the descriptor's word-2 high byte at `$0044` from `$00` to `$40`, setting MAME's 16B hide bit. The observed final palette index at each target changes from `$0AE2` (16B sprite) to the existing rotation-fill index (`202` at Y=157; `203` at Y=158). The screen RGB at both target pixels changes from `000000` to `d6d684`.

**Verified by execution:** all 20 captured screens 960–979 have equal decoded RGB between baseline and each intervention. Captured callback-979 B-sprite RAM differs at exactly offset `$0044`; the post-write dump matches the intended hide. The 16B bitmap becomes transparent (`$FFFF`) at both target pixels. Four controls, including the Y-sprite-derived `(297,159)` and three left-edge samples, keep their layer values and RGB. The screen-980 intervention changes 1,417 pixels, bounded by x=259–291 and y=57–175. All three replays give the same layer CSV, screen PNG and post-write RAM hashes. The [audit script](../../tools/phase1b_bsprite980_audit.py) asserts these conditions and emits machine-readable JSON.

**Documented only in pinned [MAME `sega16sp.cpp`](https://github.com/mamedev/mame/blob/mame0289/src/mame/sega/sega16sp.cpp):** 16B records are 16 bytes; word 2 bit `$4000` hides one record; word 4 contains palette bits; records can write nontransparent pixels to the 16B bitmap. The test verifies the behavior of that modeled path for these pixels. **Unsupported:** the semantic role of record 4 in original Power Drift code, whether it is a world-space road boundary, and the exact corresponding physical Y-Board pixel timing. Its tall, narrow affected area makes a road-width interpretation especially premature. The existing five-word Sega CD camera interface was not tested or changed.
