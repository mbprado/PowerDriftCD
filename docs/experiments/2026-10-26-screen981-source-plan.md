## Hypothesis and acceptance

**Hypothesis:** the three-slot intervention alters the native Y-sprite bitmap under the screen-981 edges, and the already frozen screen-975 five-word packet can be evaluated against those seven source-attributed rows without refitting. **Baseline:** pulse-112 callback-950 saved state, screen-981 baseline, isolated MAME 0.289, original-art 128×64 host preview and tracked arcade-to-output calibration. **Intervention:** at callback 980 set only the hide byte in each of the three private Y-sprite descriptors. **Expected evidence:** exactly three changed source-RAM bytes, three repeat runs with identical native-frame-980 bitmap and screen-981 RGB, unchanged screens 960–980, and before/after native pixel values at every measured left and right edge. The existing 16B mask must show both edge pixels clear.

**Exploratory score rule:** hold packet `[38,0,0,4,31]`, original source art, calibration and all seven rows Y=157–163 fixed. Map arcade edge coordinates with `docs/experiments/data/phase1b-road-calibration.json` and compare them with the existing `original-road-975.png` host preview generated for that packet. Report every edge delta, mean absolute edge error and mean absolute width error in output pixels. Compare with the preexisting check limits of ≤2/≤2 output pixels. Do not alter the packet, art, row set, calibration or detector after viewing the score.

**Decision language:** source attribution may be `PASS` if the intervention and native checks pass. The packet comparison may meet or miss the retrospective limits, but it cannot reopen the original forward gate or count as a clean independent adapter validation because the target and source were selected adaptively. No measured Sega CD ASIC/VDP performance, physical-hardware behavior, or world-space track geometry follows from this host preview. A later update chosen before inspecting its road edges is still required for forward validation.
