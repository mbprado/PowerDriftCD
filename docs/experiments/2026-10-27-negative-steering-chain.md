# Phase 1B: negative steering through the producer chain — 2026-10-27

## Question and frozen tests

**Hypothesis:** a new left-steering input crosses the negative, non-saturated arithmetic branch and its resulting `$8A` value reaches the already modeled `$86 → $88 → $7A` producer stages without a callback offset. **Baseline:** local `c98dbc1` on `experiment/perspective-road`, owner-private callback-950 state and isolated MAME 0.289. The [pre-target plan](2026-10-27-negative-steering-chain-plan.md) fixed previously unused pulse **80**, odd callback markers 961–999, input/target PCs, arithmetic and exact-match acceptance. No ROM, saved state, raw trace or proprietary byte sequence is tracked.

**Verified by execution:** the unchanged steering-source predictor took input-only records at `$0374D0`, froze 20 `$8A` predictions as private JSON SHA-256 `d6f3693bba776b137a51792e71881f20444d1939561143d88b0a906fa6303d55`, and only then compared a separate target-only MAME run at `$033922`. All **20/20** values matched `$FFAF` (signed −81). This is one negative quotient calculation, followed by 19 repeated copies; it is not 20 independent steering calculations. It extends the prior pulse-176 positive, non-saturated result to one exercised negative input.

## Callback order and forward chain

**Verified by execution:** a PC-only pulse-80 replay, reading no state values, recorded exactly one occurrence per odd marker in this order for all 20 markers: `$0374D0 → $033922 → $034D44 → $034DA4 → $034DDA → $034E0A`. The order supports a same-marker forward calculation across the selected main-CPU stages. These markers identify MAME callback stages, not display frames or measured hardware cycles.

**Verified by execution:** a separate chain input-only run recorded the first pre-update `$86/$88/$7A` state at `$0374D0`, per-marker `$24/$80/$91` branch inputs at `$034D44`, and per-marker prior `$7C` at `$034DDA`. The [forward model](../../tools/phase1b_negative_chain_predict.py) used the already frozen `$8A` predictions and advanced its own `$86/$88/$7A` state with the arithmetic from the earlier isolated producer tests. It did not use later observed `$8A/$86/$88/$7A` words as inputs. Its 20 three-field predictions were frozen as private JSON SHA-256 `694769daa0619a53ca35ceb8e3170a8304d5b7cf7dbffc4a15240f73c6d078a6` before a separate target-only replay at `$034E0A`.

**Verified by execution:** held-out MAME targets matched **20/20 `$86`, 20/20 `$88`, and 20/20 `$7A`** at the same markers, with zero numerical differences. `$86` moved `$0028 → $0050 → $0051`; `$88` began `$0002` and reached `$0028`. `$7A` remained `$0000` throughout because the captured exogenous `$7C` was zero at every marker. Thus the `$7A` match checks stage alignment and the zero-input path only; it provides no new evidence about nonzero `$7C` arithmetic or a moving road response. `$24` was nonzero (`$00DD–$00FE`), while `$80=0` and `$91=0`; the retain, half-input and flag branches were not exercised. Two additional independent MAME target replays produced byte-identical debugger logs, so all three target runs matched the same frozen predictions. Cache hits were not counted as repetitions.
