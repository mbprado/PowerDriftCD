# Phase 1B: pulse-204 road edge handoff gate — 2026-10-27

## Question and method

**Hypothesis:** a visible pulse-204 arcade road update can be causally tied to the Y-sprite source and aligned with the earlier predicted scalar state. **Baseline:** local `d535b28`, the [frozen edge plan](2026-10-27-pulse204-road-edge-plan.md), [pulse-204 forward prediction](2026-10-27-state24-forward-chain.md), and unchanged [coordinate calibration](data/phase1b-road-calibration.json). The first frozen target was composed screen 981, with a callback-980 hide of the three slots previously attributed under pulse 112. Its acceptance gate required at least three Y=153–163 two-sided detected rows, clear 16B layer, exact source override and unchanged prior screens. No arcade target was used to fit a five-word camera packet.

## Observations

**Verified by execution in isolated MAME 0.289:** a full pulse-204 baseline captured screens 960–982. The existing detector found zero eligible rows on screens 980–982. All three callback-980 slots were active, and hiding only those source bytes changed 24,047 decoded RGB *bytes* on screen 981 while screens 960–980 remained identical. The callback-to-screen effect is therefore observed, but the frozen screen-981 geometry gate failed because it has no detector-eligible target rows. The private screen image shows a strong turn; **hypothesis:** the detector's left/right sand-border assumptions no longer hold. The precise reason for each absent detection is **unsupported**.

**Verified by execution:** the plan's diagnostic fallback selected screen 968 because the same baseline had nine detector rows in the wider Y=130–190 scan. At callback 967, a broad hide marked 3,924 active 16-byte Y-sprite descriptors. The post-write source differed from baseline only at those descriptor hide bytes; screens 960–967 were identical. On screen 968, both detected pixels changed on all five predeclared Y=159–163 rows. The captured 16B layer classified both pixels as `clear_rotation` on each row. Under the unchanged calibration, their inclusive target spans are `[26,118]`, `[26,118]`, `[25,119]`, `[25,119]`, `[24,119]` output pixels. These are diagnostic arcade target bounds, **not** a host-renderer comparison or a recovered projection.

**Limit — INCONCLUSIVE visual adapter:** the broad hide also changes much of the scene (128,682 decoded RGB bytes on screen 968), so it establishes a Y-sprite dependency at the sampled pixels but does not isolate individual road descriptors. The pinned isolated MAME bitmap instrumentation saves native Y bitmaps only around callbacks 979–982; a native screen-968 source-pixel transparency check was **NOT RUN**. More importantly, no independently supported rule maps `$24/$8A/$86/$88/$7A/$7C` to the Sega CD curve, ridge, bank, horizon and texture words. The previous `[38,0,0,4,31]` packet came from a different steering schedule and was not scored here. A scalar match does not validate road-image fidelity. BlastEm and physical hardware were **NOT RUN**.
