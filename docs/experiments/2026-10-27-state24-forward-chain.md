# Phase 1B: earlier `$24/$8A` through a changing arcade state chain — 2026-10-27

## Question and frozen tests

**Hypothesis:** independently predicted `$24` and `$8A` values can drive a forward `$86/$88/$7A/$7C` model over 20 arcade updates without reading those later outputs first. **Baseline:** local `48619ab`, pinned MAME 0.289, private callback-950 state and the arithmetic already validated in individual producer experiments. The [pre-target plan](2026-10-27-state24-forward-chain-plan.md) reserved pulse 180 for a zero-path control and, after its frozen prediction showed no `$7C` response, previously unused pulse **204** for a nonzero test. No arithmetic or timing shift was fitted to pulse-204 target values.

**Verified by execution:** a PC-only pulse-204 replay observed one ordered sequence per odd marker 961–999: `$0374D0 → $033922 → $0343C4 → $0344A0 → $034D44 → $034DA4 → $034DDA → $034E24 → $034EF4`. The [forward predictor](../../tools/phase1b_state24_forward_predict.py) used frozen source models for `$8A` (steering byte and initial state) and `$24` (`$8C/$8E`, flags and initial global state). It used the first old `$86/$88/$7A/$7C` words and per-update `$80/$91/$69` branch inputs, then carried its own four-word state forward using the previously validated 16-bit rules and private ROM lookup. No later observed `$24/$8A/$86/$88/$7A/$7C` word was used as a model input.

## Held-out result and boundaries

**Verified by execution:** for pulse 180 the frozen forward prediction SHA-256 `dd898cb6f5c13f7dc868b09df75574a4fbef2e15eb2bec04d10f190ec2a2f080` matched **20/20** each for `$86/$88/$7A/$7C`, but `$7A/$7C` remained zero. That control does not establish a moving road-state response. For pulse 204, the upstream `$24` source and `$8A` predictions were frozen as SHA-256 `1212fee238599369827ebb07f0a63b7afe467d3353d417dbac4f9215f81252b2` and `df1418cbed4344bd24ac3bda001aab86ea5ab0c48e27162565933fea3f64960d` before targets. The full-chain prediction was frozen as SHA-256 `6a68c7fa35098f88e82def20d243eab199864d4daffc5db1c0f3660b0e1b74c1` before its target replay.

**Verified by execution:** separate target-only MAME replays matched **60/60** upstream `$24` source fields, **20/20** `$8A` values, and **20/20 each** for `$86/$88/$7A/$7C`, with zero numerical differences and exact callback alignment. Pulse 204 held `$8A=$007F`, moved `$24` from `$00FE` to `$00E0`, and ended with `$86=$FF81`, `$88=$FFC0`, `$7A=$FFE5` and `$7C=$003A`. All 20 `$7C` updates followed the growth branch; `$7A` changed on 18 updates. Two further independent target-only full-chain replays produced byte-identical logs. These are repeated updates under one held input, not independent steering schedules. The source branch remained the `$8C` path with limit three; `$80=0`, `$91=0`, and flag `$69=$20` throughout.

**Limit:** the model still receives `$8C/$8E` and branch flags from MAME. It predicts this exercised arithmetic chain from earlier state, but **does not yet predict a physical camera pose or five-word Sega CD command from track and steering alone**. `A5+$7A/$7C` changing is not proof that the rendered road contour follows it. Other branches, changing track input, and causal visual calibration remain open.
