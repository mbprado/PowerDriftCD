# Phase 1B: `$24` producer attribution plan — 2026-10-27

**Hypothesis:** the `$0C0864` (`A5+$24`) field used by the validated `$86` and `$7C` calculations has an earlier, repeatable main-CPU write path that can be modeled from pre-update state. **Baseline:** clean `ecee7de` on `experiment/perspective-road`, isolated MAME 0.289, private callback-950 state, and the pulse-200 `$7A/$7C` carry test. Its `$24` input varied during the observed window, but its producer has not been identified.

**Discovery:** on the already-used pulse 200, watch only main-CPU writes to `$0C0864` during callback markers 961–999. Record post-write PC, address and data, with no broad memory dump or descriptor modification. Inspect the privately assembled main-CPU instructions around any writer and check whether the write occurs before the `$034D44` and `$034E24` consumers. If another CPU writes the field or no writer appears in the watched window, record that precise limitation before expanding the trace.

**Prediction gate:** choose a previously unused steering schedule and freeze an input PC, exact arithmetic, 20 expected values and checksum before a separate target-only replay. Require exact callback alignment; report if fewer than 20 writes occur or if the field changes outside the chosen writer. A matched copy from a later observed `$24` value is insufficient. Stop after one useful producer calculation, or document the narrow blocker. Keep ROMs, saved states, raw logs and assembled binaries under ignored `build/private/`; no Sega CD renderer change, hardware test or push.

**Discovery result — verified by execution:** pulse 200 produced exactly 20 main-CPU `$0C0864` writes at post-write PC `$0344A0`, one per odd marker. The first 11 were `$00FE`, followed by `$00FB,$00F8,…,$00E3`. Private instruction bytes show that `$034478–$034490` subtracts the prior global `$0CEA12` from a desired `D0`, clamps the signed change to ±`D1`, adds it to `$0CEA12`, and `$034496–$03449C` copies that new global word to `A5+$24`. Capture `D0`, `D1` and old `$0CEA12` at PC `$034478` for the development control; compare the rule with the already captured pulse-200 writes. Then use previously unused pulse **188** for a held-out input-only/prediction/target-only replay. This validates the smoothing step from earlier operands, not yet the entire upstream calculation of `D0/D1`.
