## Exercised branch and prediction

**Verified by execution:** a pulse-188 PC-only development trace entered `$0343F4 → $034418 → $034448 → $034478` at each marker. Private instruction inspection shows that this path starts with word `A5+$8C`; flag `$69` bit 5 suppresses an optional half addition, and a nonzero `$5E` byte applies an arithmetic half plus quarter. It sets `D1=3`. Desired `D0` did not exceed old global `$0CEA12`, and signed `A5+$8E` was below 20, so neither the private ROM lookup nor the mapped multiplier branch was used. The [original Python predictor](../../tools/phase1b_state24_source_predict.py) rejects those unmodeled branches. It predicted **20/20** existing pulse-188 `D0/D1` pairs and **20/20** resulting `$24` values from the earlier input capture.

**Verified by execution:** the separate pulse-180 input-only run remained within that exercised branch. The predictor used only the first old `$0CEA12` word and carried its own smoothed value through the subsequent updates; later logged global values were not model inputs. It froze 20 three-field predictions as private JSON SHA-256 `969c19ae37c542da93b12849ac56764a0b18f89fa11785230f6c693e6e15cefd` **before** the operand and `$24` target replays. All **60/60** field values (`D0`, `D1`, `$24` at 20 markers) matched exactly. An unchanged second held-out pulse 204 also matched **60/60**, with prediction SHA-256 `1212fee238599369827ebb07f0a63b7afe467d3353d417dbac4f9215f81252b2`. On pulse 204, `D0` was `$00FE` for ten updates and `$009E` for ten; `D1=3` throughout, and `$24` moved from `$00FE` to `$00E0`. Neither pulse exercised the table or multiplier branch. This predicts one more upstream calculation, not the origin of `$8C/$8E` or the physical meaning of `$24`.
