# Phase 1B: predicted `$7C` carry into the next `$7A` update — 2026-10-27

## Question and frozen test

**Hypothesis:** a `$7C` value produced after the current `$7A` update becomes the input to the following `$7A` update. **Baseline:** local `41d5797` on `experiment/perspective-road`, private callback-950 state and isolated MAME 0.289. The [pre-target plan](2026-10-27-state7c-carry-plan.md) reserved previously unused pulse **200**, fixed input PCs `$034DDA/$034E24`, output PC `$034EF4`, odd callback markers 961–999 and exact acceptance before target observation. The existing `$7A` and `$7C` integer rules were reused, with a private ROM lookup. Raw ROM, assembled program, state, debugger logs and predictions remain ignored under `build/private/`.

## Forward recurrence and result

**Verified by execution:** the input-only replay recorded current `$88` at `$034DDA`, with the first prior `$7A/$7C` pair, then current `$86/$24/$8A` and flag `$69` at `$034E24`. The [forward predictor](../../tools/phase1b_state7c_carry_predict.py) computed new `$7A` from its own prior `$7A/$7C` and the observed `$88`; next it computed new `$7C` from that predicted `$7A`, its own prior `$7C`, the stage inputs and the private ROM table. It used only the **first** logged old `$7A/$7C` values as initial state. Later old values in the input log were ignored until after target validation. Twenty paired predictions were frozen as private JSON SHA-256 `7896e36ca667e5ed3868f48d6a1010a152a6966e6a1684e8b7abc994f5be14df` before a separate MAME target replay.

**Verified by execution:** held-out values at `$034EF4` matched **20/20 `$7A` and 20/20 `$7C`**, with zero numerical differences or callback shifts. `$7C` became nonzero on 19 updates and reached `$0039`; `$7A` changed on 18 updates and reached `$FFE5`. The reconstructed `$7C` branch was growth on 19 updates and zero-value decay on one. After validation, the previously ignored old-state fields were checked against the preceding predictions: **19/19** next-update old `$7A` values and **19/19** next-update old `$7C` values matched. This directly verifies the one-update carry in the exercised main-CPU schedule. Two additional independent MAME target runs produced byte-identical logs; no cache hit was counted as a repetition.

**Limitation:** the model still consumes per-update `$88`, `$86`, `$24`, `$8A` and flag `$69` from MAME. The successful recurrence establishes the update order and arithmetic dependency; it does **not** independently predict all camera or road state from steering and track data. The one zero-value decay does not validate decay from a positive `$7C`. No physical coordinate meaning for `$7A/$7C` is established.
