# Phase 1B: nonzero `$7C` producer — 2026-10-27

## Question and frozen validation

**Hypothesis:** main-CPU instructions `$034E24–$034EF4` can predict the next `$0C08BC` (`A5+$7C`) word from earlier state and a ROM lookup, yielding a nonzero input for the following `$7A` update. **Baseline:** local `83bed76` on `experiment/perspective-road`, isolated MAME 0.289 and the owner-private callback-950 state. The [plan](2026-10-27-state7c-producer-plan.md) reserved pulse 208 for development and previously unused pulse **224** for held-out validation. It fixed the input PC `$034E24`, target PC `$034EF4`, 20 odd callback markers 961–999, exact-match criterion, and private evidence boundaries before any pulse-224 target output was read.

## Reconstructed calculation and result

**Verified by execution:** the pulse-208 development run captured pre-update `$86/$7A/$24/$8A/old7C/flag69`, the divider result at `$034E5A`, and the post-update `$7C`. The private assembled main-CPU bytes identify a signed word lookup based on `$86+$7A` from a table anchored at `$000EF6`, followed by word shifts/additions, two signed `DIVS` operations, a threshold comparison, and a bounded `$7C` growth or decay. MAME's Y-Board program map and Motorola 68000 execution model supplied the address and arithmetic interpretation. The independently authored [Python predictor](../../tools/phase1b_state7c_predict.py) reads only the owner-private assembled program image for table words; it does not embed those words in Git. For the development control it reproduced **20/20** full divider-result words and **20/20** `$7C` outputs. The first lookup was at private address `$000E78`; its signed value was −193, and the first observed divider result had quotient −54 and remainder −444, followed by `$7C=1`.

**Verified by execution:** an input-only pulse-224 replay captured 20 earlier states at `$034E24`. The predictor saved 20 outputs as private JSON SHA-256 `b32f9e91ef77dfe2c3c5f65a3ea2fee2b3ffae0e7b256359a6c575ba698f0315` **before** a separate target-only MAME replay. All **20/20 held-out `$7C` outputs matched exactly**, with zero callback shift and zero numerical differences. All 20 predicted results were nonzero and followed the growth branch, from `$0001` to `$003A`; the private table addresses used in this window ranged `$000DC2–$000E78`. Two further independent target-only MAME runs produced byte-identical debugger logs. The decline, zero and alternate threshold paths were not exercised by this held-out schedule. The 20 matches validate repeated state updates across one held input, not 20 independent input schedules.

**Verified by execution from the earlier write-order experiment:** `$7C` is written after `$7A` in an update, so the newly produced `$7C` can feed a later `$7A` calculation rather than the one that already finished. Here `$86`, `$7A`, `$24`, `$8A`, old `$7C` and flag `$69` were observed at the producer input PC; they were not all predicted from raw steering. **Unsupported:** a complete steering-to-camera model or a direct physical meaning for `$7C`.
