# Phase 1B: earlier `$88` state and `$7C` write order — 2026-10-27

## Question and frozen test

**Hypothesis:** main-CPU code at `$034DA4–$034DD6` predicts shared `$0C08C8` (`A5+$88`) from an earlier `$0C08C6` (`A5+$86`) word and old `$88`. A separate write-order trace can establish which `$7C` value the already validated `$7A` step consumes. **Baseline:** local `b9c582e` on `experiment/perspective-road`, the owner-private callback-950 state and the isolated MAME 0.289 executable. The [plan](2026-10-27-state88-plan.md) froze pulse 40, input/target PCs, the arithmetic and 20-write acceptance before target observation. The shared table pointer's writer had already been observed near `$038676` in the [earlier ROM geometry report](2026-10-21-arcade-rom-geometry-to-road-image.md), so no broad pointer search was repeated.

## Prediction and timing

**Verified by execution:** an input-only pulse-40 replay recorded `$86` and old `$88` at PC `$034DA4` for 20 odd callback markers 961–999. The [independent model](../../tools/phase1b_state88_predict.py) applies the local 68000 instruction sequence: signed arithmetic half of `$86`, signed division by eight truncating toward zero to obtain a step limit (minimum one), signed difference from old `$88`, clamp to ±the limit, then 16-bit wrapped addition. The predicted-output artifact was frozen with SHA-256 `c1fa06775579f98306f65a3f4e6d35c3ef959a8157d3f17b7a03118ddf89c9b3` **before** a separate target-only MAME replay. At PC `$034DDA`, all **20/20** observed `$88` values matched exactly at the same markers. No timing shift or target-based fit was made. `$86` reached `$007F`; `$88` rose from `$0000` to `$003F`. The positive step clamp strictly limited nine updates; ten updates had zero delta. Negative `$86`, nonpositive quotient and negative clamp paths were not exercised by this input schedule.

**Verified by execution:** a subsequent read-only watch on `$0C08C8` (`$88`), `$0C08BA` (`$7A`) and `$0C08BC` (`$7C`) under the same pulse logged 20 writes at `$034DDA` to `$88`, 20 at `$034E0A` to `$7A`, and 19 at `$034EDA` to `$7C`. On every observed update the order was **new `$88` → new `$7A` → optional new `$7C`**. The first marker had no `$7C` write; the other 19 did. Thus, for this exercised path, the `$7A` step consumes the `$88` produced in the same update and the `$7C` value carried into that step from earlier state. The optional `$7C` write occurs too late to be an input to that same `$7A` calculation. This is an instruction/update ordering result, not a measured display-frame latency.

**Documented by private disassembly, not dynamically validated here:** the pointer selector around `$03864E–$038676` reads an arithmetic-device result, combines it with a word at `$0CEA38`, indexes a ROM descriptor table and writes `$0CEB00`. The earlier cold-boot report observed a replacement with `$01C9C8`; the recent table-generation trace observed two source pointers, `$02CB88` then `$01C9C8`. The exact game-state selector and whether it corresponds to a track choice remain **unsupported**. No new pointer-selection prediction was claimed.
