# Phase 1B: steering byte to `$8A` source — 2026-10-27

## Question and method

**Hypothesis:** an earlier steering input can predict the `$0C08CA` (`A0+$8A`) word consumed by the already validated `$8A → $86` step. **Baseline:** local `ce6a343` on `experiment/perspective-road`, the owner-private callback-950 saved state, and isolated MAME 0.289. The [pre-target plan](2026-10-27-state8a-source-plan.md) fixed writer discovery, a previously unused pulse 176, input/target PCs, the integer rule, callback markers 961, 963, …, 999, and exact-match acceptance before the target replay. Raw ROMs, reconstructed CPU bytes, saved states and debugger logs stay in ignored `build/private/`.

**Verified by execution:** a pulse-216 write watch found 20 writes to `$0C08CA` at debugger PC `$033922`, all `$007F`, and a separate watch found one upstream write to `$0CE0CE` at debugger PC `$037550`. Private main-CPU instruction inspection locates the actual writes immediately before those post-write PCs: `$03391A` copies global `$0CE0CE` into `A0+$8A`, while `$03754A` stores the steering-derived calculation into `$0CE0CE`. Thus the earlier `$034D04/$034D22` local `$8A` writer, which was not reached in the prior tested path, is not the producer of these observed values. The source input routine uses `A5=$0C0040`; the later copy uses `A0=$0C0840`. An initial input breakpoint incorrectly assumed `A5=$0C0840` and recorded zero hits. The corrected input-only run removed that condition and recorded 20 entries at `$0374D0`, all with `A5=$0C0040`. This correction occurred before any pulse-176 target capture.

## Arithmetic and held-out result

**Documented only** by the private main-CPU instruction sequence: `$0374D0–$037550` clamps byte `$0CFF27` to `[53,203]`, accumulates the signed change from state `A5+$16` in `A5+$18`, and recalculates only when the absolute accumulator exceeds two. It centers the clamped input at 128, multiplies by 256, divides by 150 using the mapped main-CPU hardware divider, and clamps the signed quotient to `[-127,127]` before writing `$0CE0CE`. The pinned MAME Y-Board map and arithmetic-device implementation document the multiplier at `$080000`, divider at `$084000`, signed product and signed division with truncation toward zero. The [Python predictor](../../tools/phase1b_state8a_predict.py) independently implements this integer path. It takes the first observed pre-update `A5+$16`, `A5+$18`, and `$0CE0CE`, then only the earlier raw steering byte for each of the 20 updates; it does **not** use later observed state/global words or target `$8A` values.

**Verified by execution:** the corrected input-only pulse-176 run began with raw steering `$B0` (176), previous input `$0080`, accumulator `$0000`, and global `$0000`. The first predicted calculation is `(176−128)×256 / 150 = 81` after truncation; the branch condition is met because the accumulated change is 48. Later identical raw inputs do not trigger a recalculation, so the model predicts `$0051` for all 20 `$8A` copies. These predictions were frozen as private JSON SHA-256 `9482ad4922f6702d8dd76453b82e67e5967cbed92c0ceb0d3c729bf16d4c23ac` **before** a separate target-only MAME replay at `$033922`. All **20/20 held-out `$8A` values matched exactly**, with zero callback shift or numerical difference. A further source-only replay independently observed one `$0CE0CE=$0051` write at post-write PC `$037550`. This establishes one exercised non-saturated steering-to-source calculation and its repeated downstream copy; it is not 20 independent calculations of the quotient.

Ghidra/REA, another arcade emulator, BlastEm and physical hardware were **NOT RUN**; MAME host execution speed is not hardware speed.

**Unsupported:** assigning physical camera units to `$8A`, treating the byte-to-word mapping as a complete steering/camera model, or assuming the untested negative, saturated and accumulator branches behave exactly as the local instruction reading suggests. The next useful test is a second, contrasting steering schedule that crosses one of those branches and then follows the already modeled `$8A → $86 → $88 → $7A` chain with explicit update alignment. No Sega CD renderer or five-word command change is justified by this scalar result alone.
