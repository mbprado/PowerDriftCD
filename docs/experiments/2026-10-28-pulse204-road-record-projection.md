# Phase 1B: pulse-204 projected road-like record to two Y-sprite pages — 2026-10-28

## Question and method

**Hypothesis:** the previously attributed screen-967 `$E630` and screen-968 `$C630` boundary pixels are downstream of one main-CPU projected object, so changing one projection input before its calculation should change the shared-list record, both page descriptors and visible pixels. **Baseline:** source revision `9e46b0a` on `experiment/perspective-road`, [adjacent source attribution](2026-10-28-screen967-adjacent-source.md), and [page-C attribution](2026-10-28-screen968-page-c-source.md). The previous `$7A` response was [traced to a foreground car](2026-10-28-state7a-foreground-sprite-chain.md), so it is not the target of this experiment.

**Verified by execution:** the local test used the same callback-950 saved state, pulse 204 at callback 960, and captures through callback 982. First, focused watches traced the exact source. Then a guarded MAME debugger breakpoint temporarily added raw `$0100` to `w@(a4+1c)` only when main PC=`$033D1E`, `A5=$0C1C80`, and `A0=$0C9800`. A paired breakpoint at `$033E84` logged the projected record and restored that word. A zero-delta run controlled for the instrumentation. Expected evidence was a changed projection, shared record, source descriptor and screen with the original state restored. No Sega CD renderer code was changed.

## Source and timing

**Verified by execution:** the unique 16-byte record `8B3D0020 00120024 00160022 B242003E` appeared at offset `$0260` of the `$0C9800` shared list, hence `$0C9A60`, at callbacks 964–967 and not callback 963. Eight watched main-CPU word writes at PC `$033E8E` copied the record from active object `$0C1C80` immediately after its `$033D1E–$033E84` projection. The trace's prior source-coordinate tuple was `$1B75,$0657,$0000`; the focused `$033B22` breakpoint had no hits in this window, so its geometry read had happened earlier. The broader geometry provenance is described in the [ROM geometry report](2026-10-21-arcade-rom-geometry-to-road-image.md).

**Verified by execution:** Sub-CPU X consumed this list record at PC `$00DD6A` during sequence frame 965 with `D0=8B3D0020`, `D1=00120024`, `D2=00160022`, `D3=B242003E`, `A0=$0C9800`, and `A2=$18C630`. Its `$00E0A6–$00E0E2` writer updated both `$C630` and `$E630` in that pass; the graphic word remained `$3888`. Each descriptor was unchanged between callbacks 966 and 967. The subsequent appearance on two composed screens is a page-selection timing effect, not evidence for two independent camera calculations. The exact list-head switch instruction remains **unsupported**.

## Projection intervention and visible result

**Verified by execution:** the zero-delta control matched the prior baseline on all 23 captured RGB screens. The changed run restored the input word to `$E808` after temporary `$E908`, and the projected record changed from X/Y `$0012/$0024` (18,36) to `$000A/$0021` (10,33). The entire record changed from `8B3D0020 00120024 00160022 B242003E` to `8B330020 000A0021 00160022 B2420034`. Of 276 captured geometry rows, only object 0 at callbacks 964 and 965 changed, and only their two projected fields changed. The existing fixed-point [projection replay](../../tools/phase1b_projection_replay.py), using the earlier callback-962 inputs and the correctly timed callback-964 horizontal offset, calculated both 18,36 and 10,33 exactly. This is a controlled projection dependency, **not** a prediction from steering or track state alone.

**Verified by execution:** both page descriptors changed while retaining graphic `$3888`. `$E630` changed from `0005 0690 66C3 3888 003B 7210 0011 0E64` to `0005 06A1 66C1 3888 0031 7276 0011 0E64`; `$C630` changed from `0005 068E 66C4 3888 003B 7210 0011 0C64` to `0005 069B 66C1 3888 0031 7276 0011 0C64`. Composed screens 967, 968 and 969 changed by 3,491, 4,444 and 5,845 RGB pixels respectively; screens 960–966 did not change. These are image differences, not emulated cycles or hardware speed.

**Verified by execution:** on screen 967, detected row-159–161 bounds changed from `(66,300),(64,301),(62,301)` to `(75,291),(74,291),(72,291)`. On screen 968, row-159–163 bounds changed from `(65,297),(64,298),(62,299),(61,299),(60,299)` to `(69,291),(68,291),(66,291),(66,291),(65,291)`. A fresh one-byte exact-slot hide in the *changed-input* run visibly changed the left edge at all 3/3 and 5/5 sampled rows. The right edge changed at 0/3 and 0/5 rows. Thus `$E630/$C630` remain visible contributors to the tested **left** pixels after projection, while the changed right-edge pixels have no visible RGB dependency on the tested hide. Their source identity is **unsupported** without another layer/native-bitmap attribution. The prior baseline hides had affected both sides; that result applies to the baseline composition only.

**Verified by execution:** four independent changed-input MAME runs produced byte-identical 23-screen PNG sequences, source Y-sprite snapshots and geometry CSVs. The final screen-967 SHA-256 is `922bc3127350d749ac6bc4cf8d9a9e6de9299c5cac80b3db47df039a3fbca575`. The [audit script](../../tools/phase1b_roadslot_projection_audit.py) checks controls, replay, repetitions, descriptor changes and the exact-slot RGB samples. Its ignored JSON output is `build/private/phase1b-roadslot-projection-audit.json`, SHA-256 `5f9718207c528987d900f7eb73cefd9d022a8e8bdc9a4b7111fe8fbd4cf5d8d9`.

**Limitations:** MAME 0.289 is the only emulator used for these arcade experiments; no physical arcade or Sega CD hardware was tested. The test isolates one controlled projection input and list record, not the full causal path from steering and track state. It does not establish exact page-head switch timing or assign the changed right boundary to one descriptor. No BlastEm run or Sega CD packet comparison was made. **Next hypothesis:** identify the changed right-edge native source and the earlier producer of this object's projection input, then test an independently predicted screen response without fitting to target pixels.

**Subsequent result (2026-10-28; verified by execution):** the [native-layer and translation trace](2026-10-28-roadslot-native-layer-and-translation.md) found all eight changed right-bound samples native-Y transparent and 16B covered; screen-968's five samples were causally attributed to B-sprite descriptor `$0040`. The same trace linked the selected translation `$E808` to earlier state `$0C0856=$17F8` and its prior `$17D3` base. Thus those right samples are excluded from road calibration, while the arithmetic before the state adjustment remains open.
