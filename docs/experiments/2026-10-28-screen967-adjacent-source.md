# Phase 1B: adjacent pulse-204 Y-sprite edge source — 2026-10-28

## Question and frozen test

**Hypothesis:** the three two-sided edge rows on composed screen 967 are supplied by the page-E version of the strip attributed to `$C630` on screen 968. **Baseline:** local `3bdeedc`, the [screen-968 exact-source result](2026-10-28-screen968-page-c-source.md), and the [pretarget plan](2026-10-28-screen967-adjacent-source-plan.md). The plan fixed pulse 204, callback 966, candidate `$E630`, screen 967 rows Y=159–161 and six edge coordinates before intervention. A pass required one changed descriptor hide byte, unchanged prior screens, six changed RGB pixels, and six native opaque-to-transparent words; it also required two fresh repeats.

**Verified by read-only inspection of the private baseline:** the callback-966 `$E630` and callback-967 `$C630` descriptors share the captured graphic identifier `$3888` and the tested shape/zoom and control words. Their raw position words change by −2 and +1 respectively; their page-specific next links differ. This is a targeted same-feature hypothesis, not a claim that the graphic identifier has a known track meaning.

## Result

**Verified by execution in isolated MAME 0.289 — PASS for sampled source continuity:** a separate capture build changed only the native Y-bitmap dump window to include frame 966. Its decoded screens 960–982 matched the prior binary. On the unchanged baseline, the six frozen screen-967 edge pixels map through the pre-966 rotation transform to opaque native bitmap-966 words. Hiding only `$E630` at Lua callback 966 changed all **6/6** edge RGB pixels and made all **6/6** mapped native words `$FFFF`. Screens 960–966 stayed identical to the baseline; the captured 16B layer was clear at all six edge pixels.

**Verified by execution:** the `$E630` override differed from its source snapshot at exactly one hide byte. Two additional fresh MAME runs reproduced the same six-pixel result. All three runs had identical override, screen-967 PNG and native-966 bitmap hashes; their logs were distinct because of private run paths. The [auditor](../../tools/phase1b_screen967_adjacent_audit.py) checks the source bytes, input pulse, prior screens, descriptor-field relationship, six native mappings, layer status and three-run hashes. This supports temporal continuity of the sampled Y-sprite feature across **three overlapping rows** of screens 967 and 968. It does not establish that the full road contour or every pixel of the descriptor is a pure track boundary. Screens 968 Y=162–163 had no matching screen-967 detector rows, so those two rows are **unsupported** for adjacent continuity.

**Camera-adapter status — INCONCLUSIVE:** no predicted scalar state was converted to a five-word Sega CD packet and scored here. Matching a moving Y-sprite feature is a useful arcade reference, but it does not prove that the current renderer reproduces its geometry. No host preview, BlastEm, second arcade emulator or physical hardware was run. MAME host execution speed is not original hardware performance.
