# Phase 1B: dual-schedule late road slot — 2026-10-29

## Question and acceptance

**Hypothesis:** the `$E5D0` Y-sprite slot isolated for pulse 56 also contributes visible road-region pixels in the pulse-204 schedule at the same callback/render window. **Baseline:** the [pulse-56 single-slot result](2026-10-29-late-road-single-slot.md), the common callback-950 saved state, and independent pulse-204 source/screen captures. **Test:** run an unmodified pulse-204 baseline and a callback-991 one-byte `$E5D0` hide with the same isolated MAME binary; compare source RAM, native frame 990 and composed screen 992. Repeat the exact intervention twice. Capture the sub-CPU write to the slot in both schedules. **Acceptance:** one intended source-RAM byte, a changed native bitmap and screen, no changes on other captured frames, and identical intervention outputs in three fresh MAME processes. This test does not accept a shared slot address as proof of a shared game object.

## Result

**Verified by execution — PASS for visible source in both schedules:** the pulse-204 callback-991 intervention changed only byte `$E5D0`, setting descriptor word-0 hide bit `$1000`. The renderer's page-`$E` hidden count rose from 1/99 to 2/99 at native frame 990. That frame changed **14,066 of 262,144 native 16-bit words**; composed Lua screen 992 changed **4,752 of 71,680 RGB pixels**. Earlier and later composed screens 960–1000 and native frames 988–995 were unchanged. The capture-only instrumented baseline matched all 41 corresponding uninstrumented pulse-204 screens. Two further pulse-204 trials ran MAME afresh and reproduced the same post-write RAM, native bitmap and screen-992 checksums.

| Schedule | `$E5D0` graphic word | Native words changed | Screen-992 pixels changed | Changed screen bounds | Changed X at Y=180 |
|---|---|---:|---:|---|---|
| Pulse 56 | `$3888` | 4,073 | 3,327 | 182–319, 158–205 | 183–319 |
| Pulse 204 | `$28B9` | 14,066 | 4,752 | 0–212, 176–223 | 83–134 |

**Verified by execution:** both exact-slot interventions affect only native frame 990 and composed screen 992; each has three matching fresh runs. The changed regions are different and the source graphic words differ. The pulse-56 slot contributes the gray road-surface samples fixed in the prior report. The pulse-204 hide removes a visible road-region graphic in the baseline screenshot, but no fixed three-pixel cross-schedule correspondence was established. The table gives *intervention masks*, not predicted road coordinates or a camera transform.

**Verified by execution in focused debugger traces:** the sub-CPU wrote descriptor `$18E5D0` during the callback-989 interval in both schedules. The first-word write used PC `$00E0A8`; the logged `a2` register after that read was `$18C5D2` in both. This identifies a shared low-level list writer and source-pointer value at that instruction. **Unsupported:** that the two slot instances represent the same world-space track segment, that `$18C5D2` alone identifies their game-level source, or that their screen displacement is caused by the predicted `$0CEA00` phase. The input schedules differ in steering, and other visible state had diverged before the first predicted phase difference.

**Decision:** retain the independently validated phase predictor and the two exact-slot source attributions, but do not score an arcade-to-Sega CD camera packet from these masks. A shared renderer slot is a temporary allocation, and the two source graphic words and visible footprints differ. No Sega CD renderer or five-word interface change is justified by this result.
