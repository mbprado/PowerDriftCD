# Phase 1B: forward state into pre-add position — pretarget checkpoint

**Hypothesis:** the existing `$24`, `$8A`, and `$86/$88/$7A/$7C` forward models can replace per-update observed `$86/$7A/$24/$8A` inputs in the [pre-add divider prediction](2026-10-29-preadd-divide-heldout-result.md). **Baseline:** pushed commit `9160055`, private callback-950 MAME state, isolated MAME 0.289. **Acceptance:** on a previously unused steering pulse, predict all 20 full `D0` and `$82` outputs at PC `$034F1E` from upstream model inputs and the prior `$28` word, freeze before a separate output-only replay, then require 40/40 exact word matches with marker alignment. Reject any nonzero `$A2` timer instead of applying the timer-zero model to it.

**Verified by execution, development pulse 204:** the [combined predictor](../../tools/phase1b_forward_preadd_predict.py) recomputed existing source and forward models and consumed the prior `$28` word from the private pre-add development trace. It matched **20/20 full `D0` and 20/20 `$82`** values without using the observed `$86/$7A/$24/$8A` from that trace. The timer was zero on all 20 development updates. This is a development check, not the held-out result.
