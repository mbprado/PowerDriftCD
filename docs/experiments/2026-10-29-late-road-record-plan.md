# Phase 1B: later projected record pair — pretarget checkpoint

**Hypothesis:** the main-CPU record at shared-list offset `$0240` stores the latest projected position in its first coordinate pair and the previous projected position in its second pair. The [earlier scalar-to-record gate](2026-10-29-scalar-to-road-record-plan.md) failed because it expected the newly projected `$FE7B/$0047` in the first pair at callback 990. Focused writer evidence instead placed that value in the second pair of the later callback-992 record. This is an observed timing/layout hypothesis, not a settled semantic name for every record field.

**Held-out question and acceptance:** use a later, previously unseen pulse-212 window. Predict object `$0C1D00` projected X/Y at callback 996 from marker-993 carried `$28`, marker-993 index/base, private ROM coefficient and masked callback-994 projection inputs. Then compare that prediction with the callback-996 projected words and the **second** coordinate pair at offset `$0248` in the callback-998 shared list. Require exact four-field agreement in three fresh output-only MAME runs. The predicted coordinates may be off screen; this is a numeric record test, not a visible-road test.
