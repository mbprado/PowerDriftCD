# Phase 1B: late-window road source feasibility — 2026-10-29

## Question and method

**Hypothesis:** a visible Y-sprite source can be fixed for screen 989, where the independently predicted natural phase differs between pulse-204 and pulse-56 schedules. **Baseline:** the deterministic callback-950 saved state, unmodified pulse-56 and pulse-204 screen/source captures, and the [frozen natural-phase plan](2026-10-29-natural-phase-screen989-plan.md). **Test:** follow each callback's reachable Y-sprite list, hide a bounded candidate and then one complete reachable descriptor page at each of three consecutive callbacks, and compare decoded 320×224 screen pixels with the same-schedule baseline. A useful source requires an actual composed-screen response; a successful RAM write alone does not pass.

## Result

**Verified by execution — INCONCLUSIVE for a screen-989 source:** the reachable list moved through pages `$8`, `$E`, `$C`, `$A` at callbacks 987–990 in both schedules. The previously useful `$E630` slot was reachable at callback 988, but its graphic word was different from the earlier `$3888` road-strip word in both schedules. Hiding `$E630` at callback 988 changed **zero** screen-989 RGB pixels in either schedule. In the pulse-56 callback-988 page, the only two reachable `$3888` slots were `$E520` and `$E580`; hiding them together changed zero pixels on screens 988–993. Graphic word alone therefore did not establish a visible road source in this window.

**Verified by execution:** page-wide controls hid all reachable descriptors on page `$E` at callback 988 (102 slots), page `$C` at callback 989 (102 slots), and page `$A` at callback 990 (101 slots). Each private trial changed exactly that many first descriptor bytes in the post-write 64 KiB source-RAM capture. Decoded RGB pixels on every screen 988–995 were identical to the unmodified pulse-56 baseline in all three trials. Screen 991's PNG SHA-256 was `49edceab38ec8de29aeba5031046cbc6ebbaa0430d7de84a758596f9fb624308` in all trials and baseline. These are successful RAM interventions with **no demonstrated composed-screen effect**.

**Hypothesis:** the late-window callback labels and source-list page used by the renderer are misaligned, or the modified entries are replaced before the relevant render. Offscreen/occluded descriptors are another possibility. The present captures do not distinguish these explanations. Earlier [positive Y-sprite hides](2026-10-21-arcade-visible-strip-attribution.md) and the [page-rotation study](2026-10-23-arcade-three-update-road-sample.md) establish that this override mechanism can affect other windows; they do not establish the late-window latch timing.

**Decision:** no screen-989 landmark, six-callback phase-to-pixel lead, or arcade-to-Sega CD camera packet is validated by this test. The [natural scalar prediction](2026-10-29-natural-phase-road-observation.md) remains 100/100, and the earlier bounded phase-lookup causal result remains valid. The five-word Sega CD interface is unchanged. Stop this source search here rather than selecting a target pixel after viewing these outcomes.

## Smallest next test

**Hypothesis:** a native Y-sprite bitmap capture immediately before composition, paired with the live list head/page at that exact point, will reveal whether the page-wide hides reached the renderer. Capture a short, fixed callback 988–991 window for one unmodified and one page-wide-hidden pulse-56 replay. Compare native bitmap words and list head/page *at the render latch*, then composed pixels. If the native bitmap is unchanged, trace only the list-page selection or overwrite between callback and latch. If it changes but the screen does not, inspect composition/occlusion. Freeze any resulting source slot and screen row before a new phase/geometry comparison. This is a proposed experiment, **not executed** here.
