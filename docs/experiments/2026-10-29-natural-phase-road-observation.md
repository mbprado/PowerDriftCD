## Frozen question

**Hypothesis:** a naturally varying, independently predicted `$0CEA00` phase can be aligned with a later visible road edge. The [pretarget plan](2026-10-29-natural-phase-screen989-plan.md) was committed as `c598682` before any pulse-56 target-output or image run. It fixed the pulse-204 control, pulse-56 held-out schedule, first predicted phase divergence at marker 983, nominated screens 989/990, arcade Y=153–163 sampling rows, the existing 320×224-to-128×64 [coordinate calibration](data/phase1b-road-calibration.json), and separate scalar/visual decisions. The plan stated that image differences alone would not establish a phase-to-pixel mapping.

## Inputs, target and result

**Verified by execution before target images:** a fresh input-only pulse 220 produced no phase difference from pulse 204 through marker 999. A fresh input-only pulse 56 produced the first difference at marker 983: control `$01A6`, held-out `$01A5`; later differences were one or two phase units. The pulse-56 20-update prediction file was frozen first, SHA-256 `8a03f91de7de3c9d0fe6649d5a19e0e6ffb18270847a172805c7c4ad03ff2c20`. Selecting pulse 56 after viewing its *input-only* prediction is recorded; no pulse-56 target or screenshot was viewed before the plan was committed.

**Verified by execution — scalar PASS:** a separate pulse-56 output-only MAME run matched **100/100** frozen source, preclear sum, increment, phase and offset fields across 20 markers. The predictor/validator checked the frozen input-log checksum and recomputed the model before comparing target values. This extends the upstream numerical validation to a previously unused negative steering schedule.

**Verified by execution — visual INCONCLUSIVE:** the fixed `phase1b_mild_steer_width.scan` detector found **zero** eligible Y=153–163 road-boundary rows on both nominated screens 989 and 990, for both pulse 204 and pulse 56. The already tracked calibration maps those arcade Y values to output rows `21,22,24,25,26,27,28,29,30,32,33`; with no screen-space bounds, there was no edge vector to map or score. Screen 989 did differ by 54,416 decoded RGB pixels and screen 990 by 55,442, but the **first** screen difference between schedules occurred at screen 964, long before their **first predicted phase divergence** at marker 983. Steering changed other visible state first. The image differences therefore cannot be attributed to the predicted phase. The six-label lead inferred from the earlier intervention remains unvalidated for this later track window.

**Decision:** the [prior phase-lookup intervention](2026-10-29-phase-lookup-road-edge-causal-test.md) still proves a bounded lookup-to-road-edge causal path. This natural two-schedule comparison does **not** supply an independently predicted road edge or an arcade-to-Sega CD five-word camera packet. The renderer interface remains unchanged. The right edge and other colored pixels were not substituted for the frozen absent landmark.

**Next hypothesis:** use a screen/track window with a fixed, independently attributed unoccluded Y-sprite edge **and** source inputs that vary the phase before that road record is made. Alternatively, model enough of the other camera/track state to predict the edge jointly; steering pulses are not phase-only controls. Freeze the source slot, callback relation and coordinate rows before validation. Do not fit a camera packet to the same target pixels used to select the window.
