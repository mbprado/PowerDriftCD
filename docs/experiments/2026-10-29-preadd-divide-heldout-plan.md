# Phase 1B: divide result to pre-add position — pretarget checkpoint

**Hypothesis:** the earlier `$034E24` state and prior `$0C0868` word predict the full pre-add `D0` at `$034F1E`, without observing the intermediate divider output at `$034E5A/$034EF4`. **Baseline:** pushed source `d947e1a`, callback-950 private state, isolated MAME 0.289. The [offset-source result](2026-10-29-offset-source-heldout-result.md) began from this pre-add `D0`; this test moves one calculation earlier. **Acceptance:** exact 32-bit `D0` and `$0C08C2` (`A5+$82`) for 20 odd markers 961–999 on a held-out pulse, with no target values in the input trace. A separate target-only MAME run must execute after the frozen predictions are recorded. An active `$A2` timer branch is outside this model and must be rejected rather than guessed.

**Verified by execution and private local disassembly:** `$034E24–$034EF4` computes a signed divider quotient and remainder from `$86/$7A/$24/$8A`, a ROM table word and branch state. The previously validated [`$7C` producer model](../../tools/phase1b_state7c_predict.py) already returns that divider pair. With the `$A2` timer zero, `$034F16` writes the low quotient word to `A5+$82`; `$034F1A` adds the previous position word `A5+$28` to the low half of `D0`, leaving its high remainder word intact. The [new predictor](../../tools/phase1b_preadd_predict.py) reuses the existing divider model and applies this low-word addition. Its development pulse-204 trace matched **20/20 full `D0` words and 20/20 `$82` words**. The timer was zero on all 20 development updates; this is the exercised-path boundary.

**Pretarget checkpoint — verified by execution:** a separate pulse-148 input-only trace contains `$034E24` state and `$034EF4` timer/prior-position values, but no `$034F1E` outputs. The predictor froze 20 varying full `D0` words and 20 `$82` words to ignored `build/private/phase1b-preadd148-frozen.json`, SHA-256 `3eb6b34b48bf0dba2476c619ae70899bef7113926c380404b3828e162230272a`.
