# Phase 1B: later divergent list-slot interleaving — pretarget checkpoint

**Question:** can the Sub-Y execution state at main-object entry predict a copy-slot outcome in a window where two steering schedules **actually differ**? Cached private pulse-72 and pulse-116 traces for main object `$0C1D00` differed at marker 981: slots `$0260` and `$0250`. Focused same-run MAME 0.289 traces then found the same entry count `$0025` in both schedules. Pulse 72 had one Sub-Y lock-protected count write `$0025 → $0026` before main acquired the lock; pulse 116 acquired the main lock at `$0025` and Sub-Y wrote later. This contrast isolates an entry-to-lock ordering difference, not a merely different starting count.

**Hypothesis and frozen test:** a new pulse-104 input-only capture at markers 981/983 sampled Sub-Y's CPU-local PC, object pointer and fields when main object `$0C1D00` entered `$033D1E`. It logged no later main lock/copy outputs. The model predicts **one extra Sub-Y record at each marker**. Entry counts `$0023/$0025` then predict locked/copy counts `$0024/$0026` and slots `$0240/$0260`. Marker 983's `$0129A8` state matches a previously successful development signature. Marker 981's `$012A76` state with nonzero object field `$0C` is farther along the privately inspected Sub-Y projection path than the `$0129AE` state that lost the lock in pulse 116; its `+1` prediction is an explicit **timing hypothesis**. The code path alone does not guarantee lock order.
