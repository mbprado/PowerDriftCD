# Phase 1B: later divergent list-slot interleaving — held-out result

**Result — verified by execution:** the frozen pulse-104 prediction in the [pretarget plan](2026-10-30-late-interleaving-contrast-plan.md) **failed** in three independent MAME 0.289 target runs. Each scored 5/8 fields. At marker 981 the model predicted an intervening Sub-Y record and main copy slot `$0240`; main instead locked and copied count `$0023` at slot `$0230`. Marker 983 matched the predicted intervening record and slot `$0260`. This is a useful counterexample to the short-window Sub-Y PC signature validated on pulse 132; it does not invalidate that earlier, bounded result.

| Marker | Entry count | Frozen locked / copy count, slot | Observed locked / copy count, slot | Result |
|---|---:|---|---|---|
| 981 | `$0023` | `$0024 / $0024`, `$0240` | `$0023 / $0023`, `$0230` | Failed: 3 fields |
| 983 | `$0025` | `$0026 / $0026`, `$0260` | `$0026 / $0026`, `$0260` | Passed: 3 fields |

**Method — verified by execution:** pulse 104 was reserved after development contrasts on pulses 72/116. The input-only run sampled main entry count and Sub-Y CPU-local state without opening copy outputs. The prediction was frozen in private JSON, SHA-256 `db06849c407dee616b10f10bbaa4171f43fa23d57e93ef3b859d90315c7dc61c`, and its plan and code were committed locally as `34514d8` before target capture. Each target run used a fresh ignored directory and actually executed MAME; no cache hit was counted as a repetition. Run `python3 tools/phase1b_projection_interleave_predict.py validate build/private/phase1b-interleave-late104-frozen.json build/private/phase1b-interleave-late104-target-r1` (and `-r2`, `-r3`) to reproduce the 5/8 result. The output-only debugger SHA-256 was identical in all three runs: `ed7064f9afe22d5a2ebd638a5d0146486cfb544ebc89e64552280bd68d5b6499`. Control-log SHA-256 values were `e18a9572db23291b892e67c4827e5bf0349f8470a85a64202bd77412b218e85d`, `90b07d94fba3d66769237b22ca696a77ed081a5bf69bb2404944d73b25c0cf52`, and `80308a91524ae7745dc9f1da7df30c0c6232744422d6f45bd21088a7c5a8f3c1` for runs 1–3. The control logs differ in their irrelevant MAME host-speed summary line; the target debugger observations agree. Host speed is not used as arcade timing evidence.

**Focused diagnosis — verified by execution:** one post-result, all-CPU lock trace around marker 981 showed the exact ordering. At `$033D1E`, entry count was `$0023` and lock clear. Main reached `$033E68`, acquired `$0CEB43`, and copied at `$033E8E` with count `$0023`. Main then incremented to `$0024` and released the lock. Only **after** that release did Sub-Y acquire it, write `$0025` and `$0026` in two records, and release it. The CPU-local Sub-Y tap identified `$012B60` as its count writer; the debugger watch-action `pc` is not used as Sub-Y's PC. Private diagnostic debugger/control-log SHA-256 values are `f1636312067369814e36c88e91648823f7322510cea5050373daf37017627a98` and `58046e59dbb879e8609f01129742a643ce72bf7a99855e980f3084c0a0b06916`. This explains the observed slot and shows the Sub-Y work was delayed relative to the main copy, not absent.

**Interpretation — hypothesis:** a Sub-Y PC such as `$012A76` at main entry establishes code-path progress but not enough relative execution timing to predict which CPU acquires the lock first. At marker 981 the pretarget `+1` inference extrapolated from a later PC and object fields and was wrong. The marker-983 signature remained useful in this run, but two markers do not establish a general timing rule. No post-result change was made to the frozen model or gate.

**Next bounded test — hypothesis:** instrument CPU-local Sub-Y checkpoints between its entry PC and `$012B60`, plus main `$033E68` lock acquisition, for the already divergent pulse 72/116 pair and pulse 104. Capture exact order and one immediately prior state/control field at each checkpoint. If a pre-lock checkpoint separates the outcomes, freeze a rule on those schedules and validate on a new held-out steering schedule with an actual divergent slot. Otherwise, classify this as scheduler-dependent at the present observation boundary and stop extending PC-only rules.
