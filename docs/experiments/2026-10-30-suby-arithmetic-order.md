# Phase 1B: Sub-Y arithmetic path versus main lock order

**Question and baseline:** can the Sub-Y arithmetic/branch path between `$012A76` and `$012B3A` supply a pre-entry predictor for the differing marker-981 shared-list slots? The [prior checkpoint test](2026-10-30-suby-lock-checkpoints.md) established pulse 72 copying `$0260`, pulse 116 copying `$0250`, and pulse 104 copying `$0230`. **Hypothesis:** a branch or arithmetic-device stage may explain why the apparently advanced pulse-104 Sub-Y PC still loses the main-CPU lock race. Acceptance for a new predictor would require an earlier observable dependency and a fresh held-out schedule; this run is a bounded diagnostic, not a frozen prediction.

**Method — verified by execution:** the optional `PDRIFT_PROJECTION_LOCK_ARITH=1` probe adds Sub-Y breakpoints at eight arithmetic boundaries: `$012A5E/$012A62`, `$012A90/$012A94/$012A9A`, and `$012AA0/$012AA4/$012AAA`. The existing optional checkpoint probe marks `$012A4E`, `$012A76`, `$012ABA`, `$012B3A`, and `$012B60`, while main breakpoints mark `$033D1E` entry, `$033E68` lock attempt, copy, and release. All debugger events appear in one ordered log. Shared count and lock byte are logged at each point. As before, the debugger action does **not** label `pc`/`a0` as Sub-Y register values; those fields can reflect the visible main CPU. A separate CPU-local Sub-Y count tap verifies the count writer at `$012B60`.

**Documented only from inspected pinned MAME source:** the Y-Board Sub-Y map binds `$080000–$080007` to a multiplier and `$084000–$08401F` to a divider (`src/mame/sega/segaybd.cpp`, pinned source lines 1100–1101). Private Sub-Y disassembly shows the probed code accesses those regions. The breakpoint labels identify code boundaries, not measured device latency.

**Results — verified by execution:** fresh isolated MAME 0.289 runs for pulses 72, 116, and 104 each exited successfully and preserved the earlier copy counts and slots.

| Pulse | Sub-Y path relative to main `$033D1E → $033E68` | Main copy |
|---:|---|---|
| 72 | Guard, first divider write/read, middle, two further arithmetic groups, branch, Sub-Y lock/count all occur **after main entry but before main lock**. | `$0026`, slot `$0260` |
| 116 | Main lock/copy/release occurs **before** Sub-Y guard and the same probed arithmetic/branch sequence. | `$0025`, slot `$0250` |
| 104 | Guard and first divider write/read occur **before main entry**. Main then locks/copies/releases; Sub-Y's middle, later arithmetic groups, branch, lock/count occur afterward. | `$0023`, slot `$0230` |

The pulse-104 entry snapshot had Sub-Y PC `$012A76` and count `$0023`; pulse 72 had PC `$0129C4` and count `$0025` ([pretarget record](2026-10-30-late-interleaving-contrast-plan.md)). More advanced code-path position at the entry instant did not imply an earlier count write. **Verified by execution:** the probed positive path reached the later arithmetic boundaries and `$012B3A` for each schedule. **Unsupported:** whether a device wait, CPU time-slice boundary, other interrupt, or unobserved state difference causes the relative timing; this probe recorded event order but no emulated-cycle timestamps. A branch-dependent *skip* was not observed in these selected events, but this does not characterize all objects or alternate branches.

**Probe limitation — verified by execution:** a trial CPU-opcode read-tap probe missed most intermediate instruction boundaries and repeated reads around a lock loop; it was not used as the event-order source and was removed from the tracked implementation. The device-specific debugger breakpoints produced the ordered events above. The new breakpoints preserved the known copy outcomes, but any subtler instrumentation timing effect remains unmeasured. No new held-out prediction was attempted because no earlier discriminating rule emerged.
