# Phase 0 emulator comparison — 2026-10-16

Labels describe evidence from this work, not a general compatibility rating. An untested feature is **unsupported** as a present capability claim. No physical-hardware test was performed.

| Candidate | Sega CD boot and firmware | Main/sub 68000 debugger | Word RAM, ASIC, VDP | Automation | Result |
|---|---|---|---|---|---|
| BlastEm 1.0.0, official macOS x86-64 archive | **Verified by execution:** parsed the original ISO and displayed the owner-supplied EU BIOS start screen and CD player. Disc IP marker **FAIL** in the observed run. | **Verified by execution:** main and sub 68000 debugger contexts, register read, step, memory read, breakpoint; sub-context `maincpu` command unexpectedly rejected. | **Verified by execution:** `vdpregs` showed VDP registers; main-CPU read at `0xa12000` succeeded. **Unsupported:** Word RAM ownership transaction, ASIC busy timing and cycle counters. | **Verified by execution:** GUI, bounded PTY capture, debugger `frames` advancement, screenshots. **Unsupported:** verified deterministic input replay or headless graphics output. | Primary debugger candidate; disc-program boot still blocked. |

**Verified by execution:** no candidate emulator was preinstalled in the initially checked command paths. BlastEm came from the [official 1.0.0 macOS download](https://www.retrodev.com/blastem/downloads.html); its archive SHA-256 is `2315f5f32b8400b4c56980b87043516ac9ec22aac5fdb9d3bdb97c2b236da221`. `/private/tmp/blastem-osx-1.0.0/blastem -v` printed `blastem 1.0.0` with a PTY. The initial GUI run printed `Failed to load Sega CD BIOS from cdbios.bin`; raw output and JSON remain ignored under `build/evidence/blastem-1.0.0/`. The subsequent [BIOS-backed test](2026-10-16-bios-backed-emulator-check.md) used a local firmware symlink, and Genesis Plus GX was loaded through RetroArch.

**Documented only:** primary sources used for the remaining candidates are [BlastEm's project README](https://github.com/libretro/blastem), [Genesis Plus GX's libretro documentation](https://docs.libretro.com/library/genesis_plus_gx/), [MAME debugger documentation](https://docs.mamedev.org/debugger/index.html), [MAME Lua debugger API](https://docs.mamedev.org/luascript/ref-debugger.html), [ares project features](https://ares-emu.net/), and the [ares-for-ai fork README](https://github.com/paulomanrique/ares-for-ai/tree/headless-mcp). The ares-for-ai fork itself reports Linux tests; those are **documented only** here, not independently verified. Neither MAME nor ares-for-ai was built or executed in this work.

**Unsupported:** any claim that two independent emulators executed the image's initial program or that reported wall-clock time is console performance. **Verified by execution:** both emulators reached the EU BIOS UI; BlastEm's debugger reached both 68000 contexts. The original-code marker and physical boot remain open.
