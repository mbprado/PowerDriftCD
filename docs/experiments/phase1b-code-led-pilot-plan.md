# Phase 1B code-led pilot: frozen before held-out output — 2026-10-27

**Question / hypothesis:** can the main-CPU instructions at `$034680–$0346EC` predict the next `$0C00A6` ten-bit index from state and ROM table values observed at routine entry, without reading the index or the intermediate `$0CEA18` lookup result first? This tests an earlier dependency than the already verified `$0346EC` arithmetic and avoids screen-edge fitting.

**Baseline:** clean `3a6fa81`, isolated MAME 0.289, owner-private `pdrift` ROMs and callback-950 saved state. The existing center/64/192 steering schedules and old projection traces are development evidence. **Held-out input:** steering pulse `96` at callback 960, then held through callback 1000. Use 20 producer passes at markers 961, 963, …, 999. None of the old producer analyses used pulse 96. Input capture at `$034680` may record only pre-existing state, table addresses, and flags. It must not record `$0C00A6`, `$0CEA18`, `$0CEA1C` after the routine, or any target write before prediction is frozen. A separate later replay will record the target write at `$0346F0`.

**Static rule to freeze:** interpret the MAME-assembled main-CPU ROM as 68000 big-endian words. Starting from entry-state `depth`, `A0`, `A1`, old smoothing word, state `$2A`, state `$7A`, and two branch-flag bytes, replay the exact word operations at `$034680–$0346E8`: mask depth with `$FFE0`, shift right four to form table byte offset, load `A0[index]` and `A1[index]`, update smoothing by signed arithmetic halving of the wrapped word sum, optionally add the `$2894` table correction indexed by negative state `$2A`, optionally add `$0200` when both flag bits are set, add half of signed state `$7A`, then mask to `$03FF`. This rule does not infer a physical camera axis. Reject the run if an input pointer lies outside the mapped main-CPU ROM or a different conditional path is executed.

**Acceptance:** first verify all four chip hashes and seven 16-byte main-CPU address windows against MAME's live program space. Then save an input-only trace and a machine-readable prediction artifact, including its checksum, **before** running a target-output replay. The result is `PASS` only if all 20 ordered held-out writes match the predictions exactly and the input-only and target runs use the same saved-state checksum and input schedule. Report any frame offset or differing branch as a failure, not as a fitted correction. The existing 180/180 projection result is not a substitute for this test. Stop after this one upstream output.

**Tool gate:** Ghidra/REA are optional only after a correct ROM/address mapping. The available system has no Ghidra or suitable JDK, so isolated MAME disassembly and instruction-by-instruction modeling are the bounded fallback unless a small verified Ghidra setup becomes practical. Do not copy the private assembled program or disassembly into Git. No renderer, interface, physical-hardware, or upstream emulator changes.

## Revision after input-only pointer check, still before any target-output replay

**Verified by execution:** four chip SHA-1 hashes and seven 16-byte live MAME address windows matched the privately assembled main-CPU image. The first input-only pulse-96 run showed `A0=$FFFFB000`, `A1=$FFFFA000` on all 20 passes, which the MAME main-CPU global mask maps to RAM `$1FB000/$1FA000`. This fails the original ROM-pointer acceptance condition. No target-output trace has been run or inspected. The earlier wording “ROM table” was too strong for this routine.

**Revised hypothesis and frozen validation:** capture both 4 KiB RAM tables at callback 960 before the first selected producer pass and again at callback 1000. Reject if the table bytes differ, if either input pointer changes, or if a required lookup is outside those snapshots. The static arithmetic rule above remains unchanged, substituting the earlier RAM snapshot for the assumed ROM table. The primary held-out schedule is now pulse **48**, chosen before capturing its input or target trace to exercise steering-sensitive state; the pulse-96 input-only run is a development control and will not be presented as the held-out result. Predict the 20 pulse-48 `$0C00A6` writes from entry-state values and the callback-960 RAM snapshot, save the prediction artifact and checksum, then run the target-output replay. Require 20/20 exact, callback-aligned matches. This is a predictive *producer subroutine* test from earlier entry state, not a full prediction from raw steering alone. The origin and population of the RAM tables remain a separate dependency.
